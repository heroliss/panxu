# 本机验收

这里的 Python 脚本属于可复现的工程工具。数据库、截图、原始协议记录和产物报告由 `.gitignore` 排除，不随源码提交。

## 验收顺序

1. 在源码运行严格资源检查与前端语法检查。扫描续接、任务交接、协议适配和逐项动作分别用可丢弃夹具验证。
2. `python verification/run_local_acceptance.py` 检查只读系统观察、模拟结果、夹具内容与回环模型连接。
3. `python verification/serve_v090_fixture.py --data-dir verification/<新的测试目录>` 提供本地流式模型及文件夹具，用实际页面检查按需技能、选项回答、用户直接处理、结果回流、跟随系统主题及F12开发侧栏。输出地址为随机回环端口。创建该目录下的 `stop-fixture` 文件即可正常退出并核对夹具散列。
4. 关闭旧版窗口，先预览再执行 `python verification/finalize.py --archive-previous --apply`，保留上一版程序及其 `userdata`；运行 `./build.ps1`。
5. 用独立测试数据目录启动最终 EXE，实际检查原生窗口。保存截图与验收判定，核对 EXE 散列，不能用源码页面或构建成功替代。
6. 执行 `python verification/finalize.py --tests-run <实际测试数> --health-url <最终EXE的/api/health>`。最终包必须没有 `userdata`、测试设置或凭据。ZIP 完成后，才恢复用户原有数据到本机运行目录，并启动正常窗口。

报告中的 `passed` 只涵盖其明确记录的范围。回环协议测试不等于真实云服务可用；模拟成功不等于文件被删除或系统被修改。当前没有真实执行器。

评分与稀疏继承验收使用 `python verification/serve_v0100_fixture.py --data-dir verification/<新的测试目录>`：真实可丢弃目录包含父5分/子1分、明确跳过、暂不建议、自然继承和超过一页的文件。必须分别检查直接建议、已扫描目录、筛选、分页、来源及批量选择到模拟方案，不可从单元测试推断原生UI已通过。原有用户数据与真实模型密钥不参与该夹具。

## v0.14验收重点

使用自有文件及固定后台/软件样本，注入只读身份核验夹具，不调用真实云模型、不读取用户profile、不对真实服务、启动项、进程或卸载器做试操作。新流程仍进入simulation backend；操作名称自然化不能成为真实系统调用的入口。

1. 同一来源任务分别检查建议与全部视图。建议只含有真实当前任务判断的对象；全部仅为该任务已知动作范围，不混入其他任务、全局未选软件或背景查询上下文。无task_id的文件接口继续只返回文件/目录，普通库存勾选与任务处理勾选各自独立。
2. 用相同exe路径的两个不同pid/create_time进程、同名服务与启动项覆盖exact-ID选择。选/取消其中一个不影响另一个，后台不使用目录继承、nearest规则或路径去重；文件目录的父子选择与例外继续回归。
3. 混合选择本任务内的启动项、运行服务和进程，核对每项冻结action及effect、分组确认与实际准备IDs。Stopped或未知服务不能误进默认停止集合；stop_service绝不转换为修改启动方式。启动注册状态未知仍如实显示，关闭启动项不被说成已结束进程，进程操作不被说成卸载。
4. 覆盖query/kind/评分筛选、跨页批选和游标失效。全量逻辑selection.action_groups.total与本批returned分别正确，plan.action_groups只描述该冻结批次；超过500目标提示剩余数量并逐批确认。跨筛选保留的选择在确认时完整分组，不只统计当前页或当前tab。
5. 正负ID签名、清单/选择revision、保护策略或可用action变化时旧请求拒绝；源任务范围外ID、无动作项及受保护项仍不可处理。确认和执行再核身份与action，暂停/取消及来源任务结果回流保持原合同。大批后台逐项核验可能耗时，进度/取消需真实，不许为加速跳过核对。
6. 实际页面检查已分析条目的完整用途/建议/原因/影响直接分区、不截预览，标签与底色可区分，暗浅/窄窗/长内容仍可读。未分析列表只给简短pending/本机类型说明，采集器reason不冒充AI理由；已分析未评分、只有操作方案、跳过、暂不建议、旧失效分别正确。无冻结动作不猜删除，PID、服务状态/启动方式及不适用原因可见，checkbox能区分同名对象，来源不随当前连接重标；确认全部本批实际项和impact直接可滚动核对。
7. 单项/混合动作、确认、进度、历史、撤销和失败/取消/中断使用自然动作名；统一全局模式提示仍可识别。仅检查结构化产品文案不重复“模拟”，不要把包含“模拟器”的名称、模型原文或原始收据改掉。结果表达本工具记录/核验状态，实际释放0，不出现真实服务已停止、进程已结束或文件删除成功的虚报。
8. 完整回归0.13的摘要600/1000与模块160、预算收束、公开动态，以及文件500批次与目录例外、独立查重等已有能力。源码、实际页面与最终Windows产物分别验收。该轮546项Python、149项Node、36项恢复检查及最终EXE验收已通过，精确范围和产物证据见发布记录及私有报告，不由本清单推断额外完成范围。

前端行为检查可使用`node --test tests/test_advice_presentation.cjs tests/test_cleanup_review.cjs tests/test_task_action_copy.cjs tests/test_ui_advice.cjs`；后台专项使用`python -W error::ResourceWarning -m unittest tests.test_application_selection -q`，再执行严格完整回归。单元测试不替代实际窗口的动作确认、返回、滚动、键盘、模式提示和状态可理解性。

## v0.13验收重点

使用自有临时profile、固定协议夹具与注入transport完成响应检查，不读取真实模型密钥，也不自动重放用户任务。历史`response_budget`若没有数值边界，只能证明发生过上限失败，不能补造是哪一个上限；ASCII归一化误算和纯正文局部结果误用分别验证。

1. `python -W error::ResourceWarning -m unittest tests.test_investigation_budgets tests.test_investigation_completion -q`检查官方风格SSE包装、超过旧4096帧、中文native/normalized复制、BMP/astral直接字符与Unicode转义、schema6最大字段/证据/模块，以及超语义预算仍拒绝。所有transport都为固定离线响应，不以伪造usage证明成本收益。
2. 核对响应上限来自`streaming.py`单一来源：wire16MiB、20000帧、单事件128KiB、native2MiB、normalized6MiB、文本64000字符及单响应8工具；工具参数解析后规范JSON128000字符，raw最多12倍并继续受整体限制。测试失败必须明确区分wire、帧、文本、参数和归一化计量，不把所有问题改称连接失败。
3. 四协议分别检查流/非流的明确`length/max_output_tokens/max_tokens/MAX_TOKENS`均拒绝未完成工具、报告`generation_tokens`，有usage时保留真实数字，没有时为null；请求3500与8192不得混淆。没有明确limit信号的EOF/断流保持不完整，不自动套用预算恢复。
4. 模拟连续调查直到收束，核对通常4次调查后预留2次评分/结论，或因工具预算更早收束；总请求始终不超过6、工具不超过12。模型每次最多6项，宿主30项历史与500目标手选兼容独立回归。收束不再采集，未执行调用配对返回；普通正文不写成执行结果，覆盖不足仍需补充。
5. 第一次输出预算失败后最多一次基于持久事实收束，消耗已有剩余额度；第二次失败或最后一轮失败如实停止，不重复执行半包或无限请求。`investigation_notice`的recovery_attempted/recovered、错误码及可选数值边界准确，recovered不冒充全部范围完成。检查错误trace没有失败帧、thinking或凭据。
6. `node --test tests/test_stream_channel.cjs tests/test_stream_view.cjs`覆盖当前前端会话8任务×32状态、最多4连接、默认3/短时最多8、单层回看和省略数量。4秒按reader首次观察计时，不让后台等待或保证所有中间状态均可见；错误立即优先。at是浏览器观察时间，不能解释成服务端事件时刻。
7. 在任务公开回复旁和F12面板实际核对最近动态、快速阶段切换、错误/取消、回看、窄窗滚动；主清单只保留短summary和首条紧凑留意，完整模块在分析详情。最后退订、隐藏、关闭、重开必须释放连接/计时器且保留承诺范围内的会话历史，不能复活旧回调或重绘输入表单。重启不要求保留前端活动，已保存公开回复及执行收据另行核对。
8. 用本地固定响应核对带/不带briefing的summary161字以及各工具600/1000字边界均一致接收；主清单仅160字预览，分析详情、重开与持久记录保留全文。超过工具各自上限、模块要点超过160或其他无效格式仍拒绝；不能把约80字风格指导变成有效性条件。覆盖不足、保护、范围与审批继续按原规则测试。该修正需包含在重新构建的最终0.13中，保留之前候选及其证据，不能复用旧passed判定。

离线、实际页面、最终原生产物与真实账户续接分别记录。本轮536项Python、143项Node及36项恢复检查通过；最终EXE原生接收232字摘要与合法模块并完成，具体范围见发布记录。原真实任务的两次授权续接另有私有计数报告：先保存12评分并暴露隐藏摘要校验，修后再以已有事实收束为completed；末轮无新增工具失败。该结果不代表全部厂商或所有真实任务均已验证，也不将模型元数据建议当作已执行优化。

## v0.12验收夹具与回归重点

独立重复查询使用自建临时目录与隔离`--data-dir`运行；不配置模型连接，不读取用户密钥，也不扫描用户真实资料。通过首页“查找重复文件”或`POST /api/duplicates/scan`启动，使用现有job进度/取消接口。请求只接收1–8个绝对本地目录及有界的条目、深度、读取预算；默认25000项、深度16、读取2GiB，界面高级读取预算可选1/2/4/8GiB。

1. 构造同内容不同名、同大小不同内容、单例大小及空文件，核对大小分组后完整SHA-256结果。借助测试钩子或源码检查确认没有第二轮逐字节比较；不能因为实现按块读取就称其为逐字节比对。文件内容只在本地读取，无模型请求、外发或评分生成。
2. 使用可丢弃硬链接样本，确认独立`hardlink/file_identity`组与`content/sha256`组的语义不同；共享实体不称为独立副本，不将逻辑重复大小显示为实际可回收量。哈希匹配文案不宣称数学100%证明，也不提供直接删除入口。
3. 用测试夹具覆盖保护、凭据/项目、链接/重解析、云端占位、权限失败及读取期间变化。禁止真实云下载或改动用户权限来制造场景。核对每类跳过原因与partial，不将跳过文件说成内容不同。
4. 独立触发条目、深度、读取量、1200秒协作工作预算和取消边界；只保留先前完整核验组，当前未完成大小组不冒充确认，缺口可见。超200组或2000路径条目时，`result_truncated/omitted`与已形成核验组的完整summary一致；不把返回上限、UI每页12组或组详情50行当成实际总量，也不推断未扫描范围。硬链接复用摘要时`checked_files`与`hashed_files`应有区别，组成员次数不能当去重实体数。主库存、评分索引、动作计划及文件内容在前后保持不变。
5. 实际页面核对无模型配置也能开始、阶段进度、取消、失败、无匹配、部分结果、多目录、预算选项和分页；返回不会自动取消job或误报全部完成。分别检查暗浅、窄窗、长路径与键盘焦点。旧明确选文件的校验入口仍做兼容回归。
6. 在LLM任务主线确认短结论、评分和首条重要留意直接可见，完整重点与其他提醒在分析详情；该页能读旧长摘要全文、全部模块与来源、最近公开回复；“调查过程”能看范围/工作量/事件并按需加载指导及事实分页；“调整要求”的草稿跨返回保留。左上返回沿来源页面工作，回到常用任务再进入不会丢当前任务和勾选。
7. 检查文件“查看选项”、按评分选择为单层区域，必要用途/原因/影响/保护/覆盖缺口仍可达。不能仅以`details`数量减少判定体验通过；旧软件低频说明可继续按需展开，F12技术面板仍独立。目录例外、500批次、执行暂停/取消和模拟释放0合同继续回归。

该轮候选版的源码测试、实际页面和最终Windows产物分别记录，不能用本清单或新按钮代替最终`passed`判定。算法与job专项测试使用自有文件，UI测试使用可控网络/计时器或隔离原生窗口；统计测试数与产物散列由各次报告和发布记录维护。

独立查重专项源码回归：`python -W error::ResourceWarning -m unittest tests.test_dedup -q`。该命令不替代整体回归与实际窗口检查，也不接受用户真实资料作为夹具。

## v0.11验收夹具与回归重点

使用`python verification/serve_v0110_fixture.py --data-dir verification/<新的测试目录> --catalog-size 100`启动自有文件与回环SSE模型。它复用v0.10夹具的生命周期，不读取用户模型密钥。普通任务覆盖短结论、评分优先、模块化重点/提醒/范围及较长公开正文；以包含`旧长摘要兼容验收`的目标另外建立任务，检查旧长摘要仍可阅读全文。不要将夹具中的固定建议、虚构模型用量或预置模块当作真实模型质量与成本证据。

1. 核对建议与已扫描目录两种视图；评分、继承来源、未评分、跳过和暂不建议可区别。检查未扫描目录显示缺口，展开与筛选不触发后台补扫。
2. 验证1–5分及其他分类的选择/取消覆盖完整任务筛选集合；其他任务同路径历史不混入自动初选。默认4分初选偏好可保存；高分仅初始化一次，刷新不覆盖手调；直接4分不会被超过500个继承5分挤出首批。
3. 在目录树选父目录、取消子目录、再选该子目录内一个文件，检查父目录三态及最终具体目标。取消的资料不能通过父目录重新进入计划。低分、跳过和未知允许明确手选，真保护与不支持动作仍阻；当前任务临时保留被手选覆盖时应说明。
4. 构造超过500个编译目标，核对全量总数、当前批次、未纳入数量和后续批次提示；不能将首批称为全部。正负签名、任务选择版本和筛选游标过期均应拒绝。每批最终方案必须列明当前实际目标并单独确认。
5. 模拟执行中检查逐项状态与计数、暂停后尚未提交项保持等待、继续恢复、取消保留已提交结果且剩余项标取消。旧方案版本不能控制新批次。执行不能调用模型来决定下一次删除；结束后来源任务能看到结果汇总。暂停/取消、撤销与实际释放0的语义必须分清。
6. 收到完整公开正文后，切页、重开任务和重启独立实例，核对最近接受回复仍可读且来源不被当前连接重标。传输中断仅标为未完成片段，不能覆盖持久成功回复；截断记录显示限制。流式预览完成不等于调查或清理完成。
7. 在开发面板核对真实发送的宿主上下文/工具结果是可读缩进文本，四协议外层、schema及native工具参数仍类型正确；任意用户/助手正文不被重排成该数据格式。对照未知、0、false、空集合、ID和游标，不因压缩丢失含义或扩权。

专项源码回归入口包括`tests/test_prompt_text.py`、`tests/test_prompt_budget.py`、`tests/test_findings.py`、`tests/test_catalog_selection.py`、`tests/test_cleanup_routes.py`、`tests/test_execution_control.py`与`tests/test_cleanup_review.cjs`。它们验证各自合同，不能代替暗浅主题、窄窗、键盘、滚动、三态勾选、实际SSE及最终WebView2原生操作验收。

输入度量用`python verification/check_prompt_budget.py --output verification/<私有度量报告>.json`，需要前后对照时通过`--baseline <同夹具旧基准>`读取隔离基准。只比较模型可见字符串和schema，HTTP序列化字节另列；token估算必须注明方法，没有提供方usage时保留未知。生产不依赖文本反向解析动作；测试/回环夹具可用`tests.prompt_fixture.parse_host_data`读取旧JSON或新文本进行语义对照，不在新文本中藏一份原JSON来通过测试。

本节是候选版验收清单，不是`passed`报告。各次源码、回环、实际页面与最终EXE的完成范围、失败、限制和产物散列由独立报告及发布记录维护。

## 数据边界

所有验收操作都使用本项目内的数据目录或脚本自行创建的临时夹具。禁止将用户真实资料作为删除、恢复、服务控制或卸载测试对象。原始协议可能包含路径和用户意图，只可保存在本机，开发记录默认关闭。

前端行为回归：`node --test tests/*.cjs`。技能资源也有固定白名单与散列校验；不得通过收集整个工程目录打包指南。

## v0.9 流式检查

`python verification/serve_v090_fixture.py --data-dir verification/<新的测试目录> --catalog-size 100` 提供真正的本地SSE与分片工具参数。可选 `--hold-marker verification/<测试目录>/hold-stream` 在自有标记存在时短暂停流，移除标记后继续，最多20秒。临时范围和两个随机端口由启动输出给出。

正常完成测试应在连接空闲超时前释放标记；长时间暂停可能进入传输中断场景。此时检查收到的内容是否保留、状态是否如实显示以及能否继续，不把中断记成正常完成。v0.9的原生截图分别保留实时、完整结束、中断、偏好和文件列表；原生点击与HTTP取消等检查范围分开记录，具体判定见native-agent-acceptance和发布记录。

`python verification/check_streaming.py --base-url <应用回环地址> --scope <启动输出的临时范围> --report verification/<私有报告>.json` 验证先有公开增量、后有成功终态，完整参数但终态前不执行，以及取消/EOF断流无工具事实。它只接受明确的custom/local-acceptance-fixture且无密钥的回环配置，禁止对用户真实模型运行。四种协议的真实HTTP成功与逐字节分块另由 `tests/test_streaming.py` 覆盖；不能把共用传输或Chat失败验收写成四协议分别完成了全部失败场景。

若锁屏等条件阻挡原生点击，可记录已通过的源码/最终EXE页面与HTTP范围，并保留候选产物；不得生成原生UI通过判定、冒用浏览器截图为原生截图，或跳过正式finalize的要求。


## 0.23 工具协作与用户规则

`serve_v0230_fixture.py --data-dir verification/<新目录>/source --native-profile verification/<新目录>/native` 创建4个可丢弃文件、离线SSE peer及分开的源码/原生资料目录；首次启动前为native种下3个任务。该peer只核验协议，不评估模型智能。

HTTP与原生窗口证据分别记录。活动后台取消的竞态/事务由单元测试覆盖，HTTP只验证完成取消幂等和跨任务边界；不把二者写成真实长任务或系统操作通过。500项内部投影测试保持30秒限制，并核对执行不复制完整库存，单次Windows调用仍不保证硬截止。
