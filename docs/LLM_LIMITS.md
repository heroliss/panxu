# LLM 的限制与可调整范围

核对日期：2026-11-03。本文按0.28.0实现记录；本轮放宽已完成源码回归、最终包及所列原生验收，准确范围见[发布记录](RELEASES.md)。最终EXE没有云模型调用，真实DeepSeek案例属于源码人工启动项测试。默认值不代表某位用户当前保存的设置，也不代表模型服务商的实际额度。

盘序让模型自行选择调查顺序、目录深度和建议对象。目录可以整体判断，也可以按需继续查看子项；没有“必须逐个分析所有文件”或“每轮只能建议六项”的策略要求。资源、数据格式、对象身份与操作确认分别管理，不能把它们统称为模型的思考限制。

## 本轮放宽的内容

| 内容 | 之前 | 当前源码 | 原因 |
| --- | --- | --- | --- |
| 普通建议及模型方案每批条数 | 6 | 30 | 原保存接口已能接收30项，取消不必要的小批次差异；模型可自行选择更小批次 |
| 一次查看已观察对象的详情 | 20 | 50 | 减少重复工具往返，仍要求真实、当前任务内且不重复的ID |
| 自定义服务／Ollama输出请求额度 | 3500 token | 8192 token | 与其他提供方使用相同的已有请求额度，不再按服务商标签额外压低 |

30项是单批上限，可以连续保存多批；它不是整个任务只能给30条建议。8192是程序请求的输出额度，服务商仍可能因模型上下文、账号或平台限制提前结束或拒绝请求。

复杂的专项选项包仍每批最多6组，因为每组可包含多个选项、说明与参数；普通文件或后台评分不受这个六组限制。

## 一次连续分析的资源额度

在“设置 → 连续分析资源（高级）”调整请求、工具、时间和token额度。新的额度用于下一次新分析会话；正在进行或暂停的会话保留原额度与已用量。用户在总额度耗尽后明确继续，才建立新额度并保留先前记录。

| 资源 | 默认 | 可配置范围 | 用途 |
| --- | --- | --- | --- |
| 模型请求 | 96次 | 6–1024次 | 限制整段分析持续消耗 |
| 工具调用 | 256次 | 12–4096次 | 包括事实读取和建议保存，不代表处理文件数量 |
| 活动分析时间 | 30分钟 | 1–240分钟 | 不计用户暂停时间；在下一次请求／工具前检查，正在进行的请求可在网络超时范围内收尾 |
| 已报告token总量 | 100万 | 1000–2000万 | 只累计服务商实际返回的计量；缺失或不完整会明确说明 |
| 连续无进展请求 | 6次 | 3–30次，程序设置接口 | 重复时间戳、事实ID、游标或相同读取不算新进展，避免无效循环 |
| 连续失败 | 3次 | 2–12次，程序设置接口 | 出错后允许修正，持续失败则停止并保留结果 |

内部另有6次请求／12次工具的检查点，兼容设置范围分别为4–32和6–128。检查点用于保存证据、整理上下文；有实际进展就自动续接，不能把整段额度清零。普通设置页面展示整段分析额度，避免让用户误以为每过六次就必须手动继续。

程序没有可靠的统一费用换算表，不用token或请求次数猜费用；实际费用以服务商计费为准。切换模型、暂停或中断恢复也不会自动把已有消耗清零。

## 上下文、输出与网络

这些是传输、解析和有界内存限制，当前属于内部配置。它们不是建议条数、文件总数或模型上下文窗口的同义词。

| 层次 | 当前值 | 达到边界时的含义 |
| --- | --- | --- |
| 已准备好的单次网络请求 | 192 KiB | 只计实际发送的协议对象，不把原生续接和公开副本重复计量；过大时不会发送半份请求 |
| 自动整理上下文阈值 | 96 KiB | 从持久目标、反馈和事实重建工作窗口，不表示删除全部历史或完成任务 |
| 工作证据窗口 | 约24 KiB、最多3份事实／16个完整对象 | 保存有限正文与事实引用；不足时可按ID或分页回读，不能声称这些就是全部库存 |
| 单次生成请求 | 8192输出token | 提供方提前触发输出上限会保留已有完整结果，不执行不完整参数 |
| SSE传输 | 16 MiB、最多20000帧；单事件128 KiB | 给逐字增量和协议包装留空间，同时限制异常或无尽响应 |
| 组装后的响应 | 2 MiB | 与传输包装分别计量；内部带原生续接的标准化封装另有6 MiB保护，不能当成可要求模型输出6 MiB |
| 流式单段文本 | 64000字符 | 解析器的有界文本容量；不代表普通界面鼓励长篇输出 |
| 公开回复投影与最近完整回复 | 最多8000字符 | 超长会标明截断；不能把被截断内容当成完整结论 |
| 一次响应的工具调用 | 最多8个 | 各调用均需完整参数及对应结果，不能遗漏调用结果后继续协议对话 |
| 单个工具参数 | 128000个标准化语义字符 | 转义包装最多按12倍字符留余量；相同Unicode内容不因转义方式不同而被重复收紧 |
| 网络连接／空闲超时 | 20秒 | 防止连接或非流式读取永久等待；服务商自身的排队和冷启动可能失败 |
| 流式响应总时间 | 180秒 | 取消监视器可中断本实例的读取；超时不等于模型完成分析 |

信息过大时优先分批、分页、压缩并按引用回读。出现明确输出截断或不完整参数时，当前恢复机制最多进行一次受限收束；持续失败会保留检查点，而不无限重试。不能为了“宽松”把坏JSON、断流内容或未知对象解释成成功。

## 采集、分页及持久记忆

| 内容 | 当前程序边界 | 如何继续 |
| --- | --- | --- |
| 读取清单／扫描结果 | 模型每页最多40项；对象详情每批50项 | 用分页、搜索、类型筛选和已观察ID继续查看 |
| 完整事实回读 | 每页20份，按ID最多12份 | 继续分页；事实目录与正文分别提供，避免无差别重复发送 |
| 普通用途、原因、影响 | 各最多400字符 | 每个字段保留与本对象相关的信息，跨对象拆分保存；不把完整报告塞进某一条原因 |
| 结论与问题 | 结论最多1000字符；问题最多600字符、2–5个选项 | 公开说明与工具结果分开，问题用于影响判断的实际信息缺口 |
| 界面重点模块 | 重点3条、提醒2条、范围2条，每条160字符 | 只控制固定界面摘要，不能据此假装全部事实只剩这些内容 |
| 专项说明 | 6组／批，任务中最多30组 | 更新已有专项或缩小任务；每组选项2–5个，避免堆叠重复问题 |
| 本地重复内容比对 | 旧ID工具每批20个文件；目录异步工具可配置最多10万条、深度32、读取8 GiB | 这是磁盘读取工作量，不能通过“模型没有token消耗”就无界读取；结果可分页回读 |
| 增量采集 | 每步1–512个工作条目，默认256；模型阅读页40项 | 使用扫描ID继续，完成采集不代表每个对象都已分析或可删除 |
| 任务身份／扫描索引 | 单任务身份集合最多5万项；单个持久扫描索引最多10万条 | 过大须分范围，未覆盖部分明确保留；不是整台电脑只能有这些文件 |
| 事实保存 | 每任务最近300份、全局事实正文最多32 MiB | 有界保留不等于无限记忆；早期正文可能已被淘汰，不能承诺任何历史永远可回读 |
| 过大的单份事实 | 超过256 KiB保存带截断标记的摘要／预览 | 重新按对象、分页或具体工具查询；预览不是原始完整证据 |
| 经验指南 | 发现目录通常约3000估算token／最多10项，正文页约4000估算token，内置单资源32 KiB | 用cursor继续；这些是本机经验，不是当前电脑的事实 |

普通主流程通过目标驱动的`TaskHarness`持续分析。兼容旧接口的`ModelAssistant.analyze`还有独立的4轮、8次工具、5000项库存上限；它不是主任务会话的96次请求机制。旧接口不能被描述成整套产品没有其他限制，也不应用旧数字解释主界面的持续分析。

## 保留的接口与操作边界

- 模型只能调用实际提供的工具，参数必须符合明确的类型、数量和枚举。建议保存、操作计划、用户选择、批准和执行结果相互独立。
- ID须来自本任务已观察范围，身份和签名仍需匹配；过期建议、目录子项例外、用户保留及保护规则不能因增加预算而失效。
- 个人资料最终由用户选择。模型评分、问题回答、高分自动勾选均不表示执行授权。开启建议不能推导为停止操作，服务运行状态不能推导为服务启动方式。
- 完成必须与实际覆盖一致；未知、未扫描、明确跳过及无法建议分别表达。程序不为通过完成检查而补造中间分数、零占用、依赖关系或实际处理结果。
- 当前只有模拟执行器。真实文件删除、进程／服务／启动变更、迁移、卸载和隐私清理尚无对应真实适配器，不能用配置解锁。
- 任意控制台、用户批处理、通用文件正文读取及联网调查尚未开放。这些是工具能力缺口，不是要求模型停止思考；以后增加时仍需与用户范围、界面反馈和结果记录衔接。
- 外发路径偏好、密钥保护、凭据目录及来源校验继续生效，不因“尽量宽松”默认增加外发内容。

后续原则是放宽固定调查套路和不必要的小批次，把资源控制做成透明、可调整的总额度；保留真实范围、正确身份、明确用户意愿和可核验结果。程序应帮助模型取得足够信息并表达建议，不用隐藏规则让正常任务过早停止。
