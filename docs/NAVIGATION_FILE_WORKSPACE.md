# 导航与“所有文件”工作区：下一轮方案

日期：2026-11-02。状态：0.19已增加“清理工具”和建议专项往返；本文规划的“常用任务/当前任务”拆分及完整盘符浏览仍未实施。当前“我的文件”继续只表示已观察清单，不能仅凭名称宣称磁盘全覆盖。

## 当前能力与缺口

| 当前已有 | 仍需开发 |
| --- | --- |
| `windows.disks()`提供可访问盘符与容量，bootstrap可显示磁盘 | 从磁盘根目录开始、打开一层才枚举一层的文件浏览 |
| `GET /api/files`查询已保存的FileCatalog；目录桥接节点用于导航 | 它不是实时文件管理器，不能仅改名就声称显示磁盘全部内容 |
| 有界扫描、可续接索引、元数据、保护和部分覆盖状态 | 浏览枚举与LLM调查分工、目录过期刷新及浏览缓存生命周期 |
| 直接/继承/未知建议、版本化选择和冻结确认 | 在完整浏览中清楚表达“仅浏览”“直接分析”“继承”“超出旧覆盖” |
| 文件可手选并生成user_direct模拟方案，无需模型再发命令 | 真正删除、回收站/备份、恢复验证等真实执行适配器 |

## 导航分工

左侧规划为“常用任务”“当前任务”“所有文件”“后台与软件”“清理工具”“操作记录”“设置”。“我的文件”改称“所有文件”应与真正浏览能力一起交付，避免先用名称制造完整覆盖的错觉。“清理工具”及额外建议详见[统一能力方案](CLEANUP_TOOLBOX_AND_EXTENSIONS.md)，同样尚未实施。

- **常用任务**：少量目标快捷入口，不维护第二套扫描或选择实现。清理C盘、某磁盘、某目录将目标和授权位置交给同一文件工作区，并关联调查任务；纯查看位置不自动分析。后台/软件及独立查重仍进入适合其对象和事实工具的工作区。
- **当前任务**：会话、问题、进展、短结论、覆盖缺口与操作结果的中心。提供“在所有文件中查看本次结果”链接，以task_id/范围/筛选打开共享文件视图；不再复制一份完整文件管理器和独立勾选状态。
- **所有文件**：位置、文件和目录的唯一浏览与处理工作区。顶层显示磁盘，支持路径与面包屑、当前层浏览、评分筛选及按需分析；可查看某任务结果，也可退出该筛选回到位置。后台实体继续按独立ID，不套目录继承。
- **清理工具**：常用系统配置、缓存和隐私操作的直接入口，同一适配器也供模型按需调用。只展示少量常用项与分类/搜索；设置跳转与直接执行分别标明，额外建议仍归当前任务，不另建任务/历史/确认体系。

导航切换保留位置、过滤和草案；返回不是取消、撤销或批准。一次展示最重要的目标、当前位置、必要状态和一个主操作，详情继续分层。

列表建议可原位附加一个专项入口，进入“清理工具”、软件流程或同任务的额外建议，再带结果返回原位置；关联、续接和执行后核验见[专项往返设计](CLEANUP_TOOLBOX_AND_EXTENSIONS.md#从已有建议进入专项清理再回到原现场)。不增加平行清单、不改变现有排版和普通操作；明确以专项工具替代目录删除时，不能继续套用普通delete默认动作。专项往返已随0.19实现；完整导航及实时文件浏览仍待开发，取舍见D056、D057。

## 打开一层，只读取一层

增加独立的只读“当前目录直接子项”枚举服务：分页/有界工作，返回名称、类型、条目大小、时间和文件身份；复用既有元数据构造与路径保护，**不调用递归扫描来伪装浏览**。进入子目录才读取其直接子项。后台扫描和模型调查可以复用同一批已有观察，避免浏览一次、分析又完整重读一次。

磁盘根入口不等于允许扫描整盘、上传正文或扩大某个旧任务的处理范围。目录枚举使用明确位置能力和稳定句柄/游标，排除链接循环及云占位取回；权限拒绝、卷拔出、变化、预算和取消分别返回状态。既有重解析点、凭据和保护规则继续应用，不能为浏览而绕过它们。

目录缓存与当前观察、模型建议是分开的层次。缓存有观察时间与版本；位置变化或签名不一致时失效，刷新只重读当前层。枚举完成仅说明这一层已读完，不证明全部子树已扫描；目录聚合大小未知时写“未统计”或“已观察下限”，不能显示成0。

按评分或名称筛选时，默认只筛已有观察，明确标出范围；不为找到全盘匹配项偷偷递归。需要更广结果时，由用户目标或模型调查明确启动有预算任务。

## 进展与建议表达

分别记录当前层枚举、子树观察和模型分析覆盖。未知总数不生成假百分比；可以显示“已查看N项、还有M个已知目录待看”，不能把M称为整盘剩余。继承项不计作逐项分析完成。

每个对象区分：未分析、直接建议、继承建议、明确跳过、调查后暂无建议及失效。继承标明上级、来源时间和“未逐项分析”；只有有效且明确涵盖子项的建议可传播。新浏览到的内容不自动扩写成旧模型已检查，超出原覆盖或来源过期时提示重核。颜色、进度和目录勾选不代替这些事实。

## 共用数据与操作主线

使用同一对象ID/文件身份、观察版本、建议来源和选择编译核心。任务结果保存对象引用及自身来源，不复制新文件对象；全局展示可关联最新有效建议，仍能回到各任务原始事实与旧来源，切换模型不能改署名。选择草案按来源/授权上下文保存，同一上下文的不同入口共用，别的任务不自动合并选择或复用批准。

共用流程：浏览/筛选 → 按需分析单项、勾选或目录 → 阅读建议 → 调整勾选与子项例外 → 编译冻结方案 → 明确确认 → 记录逐项结果。任务页只保存会话与对该工作区的引用，保留来源任务的授权边界；把旧任务结果映射到浏览器不授予其他目录动作资格。

普通文件也允许用户不经LLM直接选择删除意图。未评分、跳过或暂无建议不是强制先分析的理由；仍须取得实际对象身份/签名，核对真正保护、范围、目录完整性和明确动作，再进入相同预览/确认。当前只写模拟收据、实际释放0。未来真实删除必须另立执行门槛：可用回收站或备份、永久删除说明、逐项结果及恢复验证，不能通过换导航或按钮名开启。

## 分步实施与验收

1. 提取共享路由、对象引用和选择核心，当前任务改为会话摘要加结果入口；保留0.18过滤、例外与冻结确认恢复。
2. 开发直接子项枚举和有界缓存，以自有大目录、无权限、链接、云占位、卷变化及取消夹具验证；实际文件浏览具备后再正式改名“所有文件”。
3. 接入逐层进展、直接/继承来源与旧覆盖核对，让常用目标进入同一工作区，复用已取得事实而非补扫全盘。
4. 验证两入口引用同一对象和选择、任务范围不外溢、跨页/目录例外、失效与重启恢复；再做暗浅/窄窗、键盘/文本选择、最终原生与数据恢复验收。

实现前仍需选定具体枚举预算、排序/缓存失效策略及新版DTO。本文不给未实现端点起一个看似已经可用的API名，也不提前写测试数量、性能或最终通过结论。
