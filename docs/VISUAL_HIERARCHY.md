# 盘序文字与视觉层级

更新日期：2026-11-02。**v0.9.1 本机便携版已通过本轮验收**。这里记录设计规则、实现取舍和明确的验证边界；不把已查场景扩大为所有模块、状态的原生全测。最终产物与确切验证范围统一见[发布记录](RELEASES.md)，决策依据见[决策记录 D033](DECISIONS.md)。

## 使用场景与保留的身份

这是面向普通用户的 Windows 11 桌面操作界面，采用 Operate 模式精修。用户先看懂结论和下一步，需要时再了解原因、影响、路径与工具依据。设计感来自清楚的角色、稳定的字阶、适当留白及准确状态，不依靠更多按钮、装饰卡或更亮的颜色争抢注意。

继续使用 `Segoe UI`、`Microsoft YaHei UI`、`Microsoft YaHei` 与系统 sans-serif 后备。中文由本地 CJK 字体承担，不下载品牌字体，不引入字体 CDN 或额外字体家族；实际缺字、字重和缩放效果仍需在 Windows/WebView2 中检查。现有暗色、浅色和跟随系统身份保留。

## 六个主要文字角色

数值以浏览器默认根字号 16px 为参考，通过 rem 定义，不能锁死用户缩放。它们是主要阅读角色，不要求所有紧凑入口和既有控件都机械使用同一字号。

| 角色 | 基准 | 用途与层级 |
| --- | --- | --- |
| page | 28px / 1.75rem | 页面标题，说明当前正在做什么 |
| section | 18px / 1.125rem | 分区标题与当前需要回答的问题 |
| lead | 16px / 1rem | 本轮主要结论，少量强调，不把长正文整段加粗 |
| body | 14px / .875rem | 用途、建议原因、影响、公开回复和主要解释 |
| label | 13px / .8125rem | 字段名称、次级操作、解释标签与必要帮助 |
| meta | 12px / .75rem | 路径、时间、来源、分页、短状态标签等辅助信息 |

主阅读量度为 `70ch`、正文参考行高 `1.85`；中文实际行长还取决于字体及窗口宽度。标题、正文和长名称应自然换行，标题平衡和正文 pretty wrapping 作为渐进增强；不依赖手工插入断行维持某张截图。主文字使用 `--ink`，辅助解释使用 `--muted`，不能因进入折叠区就把所有实质内容统一压成 12px 灰字。

## 文字、底色和状态的共同语义

共用 `.semantic-tag`，通过 `data-tone` 选择五种语义。标签必须有明确文字，状态还由位置和相邻说明表达，不能只靠颜色判断。

| tone | 颜色方向 | 适用范围与限制 |
| --- | --- | --- |
| info | 蓝 | 分析建议、待确认动作和预演核对；模型接收完或有建议不等于真实处理成功 |
| warning | 琥珀 | 需要用户选择、待继续、状态变化或需要注意的内容 |
| danger | 红 | 已发生的错误、未完成或失败，配清楚原因及可用下一步 |
| success | 绿 | 有明确证据的成功，例如固定工具往返连接验证通过；不泛化为全部账户或未来请求都正常 |
| neutral | 中性色 | 来源、保留选择、未知及一般辅助状态；不借绿色暗示清理或核验成功 |

前景和底色通过主题别名映射已有 `--blue`、`--amber`、`--red`、`--green`、`--muted` 与对应 surface token。组件不另写一套暗浅硬编码颜色。标签保持克制、可换行且宽度有界，不把整篇回复涂色，不额外添加一层卡片。

任务“本轮建议”和预演“已核对”使用 info；“待你确认”“调查待继续”使用 warning；“调查未完成”使用 danger；暂停、保留与撤销预演使用 neutral。模拟状态、连接状态、模型回复接收状态和真正的执行结果不能混为一种绿色成功。

## 按内容分工

- 任务结论拥有第一阅读位置；状态标签只在需要解释当前阶段时出现，不在所有地方重复播报。
- 建议标题与状态明确分工，名称先帮助用户认出对象，用途随后解释；建议原因、影响使用 label/body 角色。路径保留 meta 层，完整位置仍可查询。
- 结果拆成对象名称、状态标签和解释正文；保留“预演”“实际文件和系统未改动”的说明。失败或待核实不得因配色调整而弱化，也不把模拟结果写成已释放空间。
- 问题先说明需要决定什么，选项标题与描述分层；保持无默认答案、可自由补充及暂不回答，不增加新的选择步骤或按钮。
- 文件名称先于位置、类型和来源；容量等比较数据可使用等宽数字。维持每页 50 项与有界 DOM，不能为视觉对齐重新引入全量文件展示。
- 开发通信先看角色和公开正文；系统提示、上下文、事实、工具、技能和原始诊断继续折叠分层。正文不是代码字体，时间/来源是 meta，真正代码与 JSON 才使用等宽字体。

普通层仍是一项主要下一步。此次不改变折叠默认、建议/处理选择分离、按钮、请求、权限或个人决定权，也不把新讨论的通用控制台能力计作已实现。

## 实现边界

`web/style.css` 继续承担基础布局、控件、主题 surface 与既有兼容规则；新增 `web/hierarchy.css` 统一阅读角色、语义状态和主题别名。任务与通用列表用明确的类表达内容职责，避免靠宽泛的 `details p` 或失配的直接子选择器决定重要正文样式。

LLM 原文继续通过 `textContent` 生成文本节点，保持内容与顺序，不增加 Markdown/HTML 解释、自动富文本、模型生成样式或任意 UI。公开流式文字仍按 grapheme 追赶，修订保真、减少动画、隐藏暂停、断连保留和有界通道按 D032 处理；字号调整不能破坏这些生命周期。

当前只有模拟执行器。17 类指导、22 个任务工具、身份/保护/范围检查、隐私与凭据处理均不因视觉变化扩大；原创许可与第三方公开二进制来源待办不变。

## 本轮验收与重访条件

本轮 325 项 Python 和 73 项 Node 回归通过，机械检测报告为 `[]`。深浅主题五种 tone 的前景/底色组合最低对比度 5.49:1；该结果针对这些主题组合，不等于已测每个控件、禁用态或叠加表面。持续目标是小正文至少 4.5:1、大字至少 3:1。

源码实际页面核对暗浅主题与 960×680 无横向溢出；开发角色正文为 14px，原始 JSON 默认未生成 pre，未发现脚本错误。原生窗口实际核对浅/深主题的建议，并操作问答和文件搜索状态。结果分行新 DOM 只沿用已有回归证据，未另外声明原生逐状态验收；没有据此宣称所有模块、字体后备、缩放、长路径或全部交互状态均已原生全测。完整范围见发布记录，源码静态检查与浏览器截图不替代最终原生证据。

如果真实场景仍要求反复展开才能理解风险、增加字号使主操作不可达、主题状态容易误判，先调整角色、间距和必要信息的位置，再考虑密度选项。只有出现平台字体缺字/可读性问题或用户明确要求品牌更换时，才重访字体选择。增加富文本、通用控制台或真实执行属于独立功能决定，不夹在本轮视觉精修中交付。
