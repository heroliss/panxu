# 下一阶段方案：由目标驱动工具协作

状态：**方案，尚未实现**。本文不属于0.22.1已交付能力，也不改变当前仅有模拟执行器的边界。2026-11-02根据用户讨论记录，作为下一阶段实现方向记录，尚未开始实施。

## 面向普通用户的入口

48项工具保留为可搜索、按分类及常用程度排列的手动工具箱，供有明确需求的用户使用。普通流程仍从“清理系统盘垃圾”“清理磁盘或目录”等目标开始，不要求用户先认识48项工具，再自行选择调查路线。

普通流程拟为：目标和范围 → 轻量诊断摘要 → 模型按需深入 → 可勾选的建议及选项 → 确认具体操作 → 进度和结果 → 继续或结束。模型负责解释、取舍和建议；程序负责取得可靠事实、呈现选项以及落实操作。

## 诊断不等于逐项深扫

- 程序先根据目标、系统环境和已有观察判断哪些工具具备检查条件；检查条件不满足、尚未实现采集器或权限不足，应分别表达，不自动推导为“无需清理”。
- 轻量诊断共用系统、卷、已知缓存位置等采集结果，保留观察时间、范围和完整性，避免同一系统快照被多个工具重复读取。
- 先向模型提供有意义的紧凑摘要：已观察占用、可能相关的能力、需要参数或仍未知的部分。未观察不补0，没有估算不声称可释放空间。
- 模型决定进一步检查哪些工具或目录，以及是否需要用户补充使用偏好。大目录、长时间哈希、隐私正文等昂贵或敏感读取不混入默认轻量诊断。
- 不把48项完整深扫结果一次塞给模型，也不把适用性筛选变成固定清理推荐规则。

## 一份能力目录，按需取得完整协议

手动界面和模型调用使用同一能力目录。目录区分发现、诊断、建议、执行及结果读取，注明输入、输出、成本、参数来源、是否需要用户选择和当前实现状态。

发现时只返回名称、用途和关键前提；模型选中某项后，能取得完整且紧凑的参数与结果schema，包括字段名、类型、默认值、必填项、枚举、单位和未知状态含义。不能只给用户可读标签，让模型猜测`project_path`等字段名。

每次结果使用稳定对象/任务引用，附观察时间、来源、完整性、跳过原因和后续读取方式。较大结果分页保存，模型按引用读取，不要求反复扫描，也不依赖聊天窗口保留所有原始结果。

## 重复文件使用已有本地引擎

现有目录查重引擎继续负责按大小分组、SHA-256校验、硬链接区别、进度和取消。模型不计算哈希，也不因同名、同大小或“较旧”便断定副本应删除。

下一轮拟把同一引擎接入任务工具：启动查重任务、读取进度、分页读取结果及取消。输入使用本次已选择范围的引用，结果归入原任务事实；模型可以自行决定何时查、在哪个已授权范围查、如何解释结果。查重结果可用于建议，不能直接变成删除授权。

## 建议、选项与结果形成闭环

建议可以关联文件、程序或专项工具。模型提供标题、原因、影响、清理倾向以及少量合适选项；界面使用统一组件显示，具体参数和必要信息按需补齐。

用户选择某个工具后，程序可以直接准备并确认具体操作，无须再让模型重复发起同一命令。用户的执行、拒绝、修改、取消以及实际收据均回到原任务；“打开”“接受建议”“完成模拟记录”“真实执行成功”保持分开。仅取消剩余操作时，不声称已完成项目被撤销。

## 放宽判断路径，严格执行协议

经验指南作为按需读取的软指导，减少固定调查顺序、固定推荐项数和重复提问；允许模型依据实际证据提出不同取舍、解释不确定性及建议其他合适能力。

工具与UI协议仍严格验证：字段、参数、对象身份、范围、版本和结果状态必须有效；用户明确保留和操作意愿、文件变化检查及真实收据继续由程序落实。严格格式用于可靠对接，不用额外规则替模型决定哪些内容“应当无用”。

预算应体现实际工作量，并支持配置、检查点和中断后续接。长诊断或哈希作为异步工作，不让模型反复轮询消耗会话额度。预算不足时保存已查内容与剩余工作，允许继续；不把一个固定6轮/12工具配方当作所有任务的最终能力边界。
