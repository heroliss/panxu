# Harness 沟通与证据交接

更新：2026-11-02，0.21。研究依据见[官方资料与技能审阅](research/harness-design-2026-11-02.md)。模型负责调查方向和业务判断；宿主负责对象身份、范围、协议、预算、持久状态和结果核验。

## 本次失败与修复

最近的后台分析确实取得了软件对象，`read_facts`也返回过完整正文。旧循环按内部JSON大小触发上下文重建，随后只留下事实ID；已有正文因为仍可从数据库读取而从重建上下文移除，评分阶段又未提供读取工具。最终模型没有可达证据，返回needs_input。工具采集失败和接口鉴权错误均不能解释这条轨迹。

重建现在使用同一入口，涵盖压缩、模型切换、输出恢复和任务续接。除了目标、保留意愿、范围和事实索引，还从本任务持久事实恢复有界工作证据：默认最多3条事实、16行完整对象、24000 UTF8字节。显式按ID读取的事实优先；普通历史分页不把整页指南优先于对象事实。没有扫描或网络副作用。

工作证据保留原ID、观察时间、来源、范围、未知/0/false和分页。完整行放不下时退回可回读引用，不截成半个对象。只有相同ID、观测时间、签名且所有字段完全覆盖的重复观察才用来源引用代替；不同版本或额外证据不合并。partial、shown/omitted、去重引用和真实未表示数量明确分开，不能把部分窗口当作完整扫描。

评分阶段仍可回读已存事实；最后一轮仅基于已经提供的正文提交结论或必要问题。可用工具列表与实际执行检查一致。后台任务不向模型提供无可遍历位置的文件调查工具，持久事实仍只读当前任务，不扩展操作范围。

## 输入、输出与预算

普通沟通使用可读文本，固定结构化写回使用原生工具参数；程序不从自然语言或手写JSON报告中猜删除动作。工具参数错误返回稳定code、缺少或接受的字段及合法下一步；错误内容不回显任意参数值、密钥或内部异常。

压缩阈值按模型可见消息的UTF8估计计算，目标96KiB，排除内部续接副本；它不是token计量，也不是厂商context窗口。最终192KiB请求上限仍在协议转换后按实际wire检查。四协议的合法续接不会因为宿主同时保存了原生副本和公开工具调用而被重复计费到输入预算。

现有6次响应/12次工具上限保持，末两轮为评分和结论留预算；中断或输出恢复不重放采集、批准或执行。工具列表的简化按实际对象范围进行，不把“少于某个固定数量”当作质量指标。

## 系统工具与文件分析共用任务

首页“清理系统盘垃圾”从SystemDrive解析真实系统盘，旧c_cleanup仍兼容。程序直接提供Windows临时文件、组件维护与系统回收站三条独立建议，每项可以查看方案或暂不清理；无需模型生成或批准。文件调查继续使用同一LLM任务与按需工具。全局“清理工具”卡片直接打开工具页，不请求模型。

固定建议不可被模型覆盖。用户可在模型调查期间选择系统工具；选择写入独立账本并在公共任务视图回填，不覆盖正在运行的任务大快照。普通模型建议仍保留忙碌与版本核对。

工具活动区分opened、accepted、declined、answered、cancelled、completed、interrupted、undone。打开或接受不是执行，模拟完成不是真实系统已修改。标准工具名、时间、状态和固定计数可提供给模型；原始参数、路径、任意标题、消息和密钥不进入活动上下文。不同任务与全局直用活动由宿主标记关系，其他任务的拒绝仅作背景。新活动会在下轮模型请求前同步，更多记录可按需读取。

## 验证边界

离线协议回归覆盖：大结果反复压缩后仍有据评分、读取旧事实、换模型、输出恢复、参数错误后修正，以及预算/范围和工具调用配对。原失败数据在隔离快照中恢复出16个唯一对象的有界正文，不重新采集或调用云模型；这证明正文可达，不等于真实DeepSeek重新分析已通过。

本构建仍只有模拟执行器。真实文件、注册表、启动项、服务和隐私设置不因这些沟通变化而获得修改能力。最终包、原生界面与原资料恢复的确切通过范围见发布记录，不能由单元测试或研究文章代替。
