# 实现状态与路线图

更新日期：2026-11-02。本目录将持续作为盘序的长期代码基地，后续开发以可审阅的 Git 提交积累。下列状态区分读取真实系统信息、修改工具内部模拟记录和真实系统操作；不能互相代替。

## 已实现

| 能力 | 只读状态 | 模拟状态 | 真实执行状态 |
|---|---|---|---|
| 常见应用缓存 | 有界检查受支持的当前用户受管位置，验证可再生成性与目录完整性 | 可以生成计划并写入处理记录 | 未实现真实删除或清缓存 |
| 用户指定目录 | 有界扫描、项目与凭据保护、重解析点排除、版本检查 | 支持用户明确选择后的文件处理计划 | 未实现真实删除、移动或恢复 |
| 下载和个人创建内容 | 按文件元数据解释；未知用途保持个人决定 | 只能由用户最后选择，不能混进推荐默认批次 | 未实现真实处理 |
| 启动项 | 支持部分 Run 注册项和启动文件夹；不代表全系统或实际启用状态 | 可记录模拟禁用 | 未实现真实禁用、还原或全局枚举 |
| Windows 服务 | 只读枚举和基本状态，不提供完整依赖审计 | 可记录模拟停止 | 未实现真实停止、启动或修改启动方式 |
| 进程 | 只读进程与工作集快照，有采集预算 | 可记录模拟停止 | 未实现真实结束或挂起 |
| 已安装软件 | 只读传统桌面卸载注册项；非所有 Store 应用 | 可记录模拟卸载 | 未实现调用卸载器或真实还原 |
| 浏览器隐私 | 识别并保护部分敏感路径，未读取账号数据库 | 不提供隐私清除操作 | 未实现 Cookie、站点数据、历史或密码清理 |
| 重复文件 | 对明确选择的文件进行有预算的本地哈希校验，区分硬链接 | 可继续使用普通文件的手动模拟计划，不自动删副本 | 未实现真实去重删除 |
| 处理记录 | 可查看本地计划与模拟批次 | 可以撤销和重置工具内部覆盖状态 | 不具备真实文件恢复能力 |
| 智能建议与任务循环 | v0.3 支持按需目录/软件调查、重复核对、经验查询、持久目标与反馈，以及旧顾问接口 | 用户审阅版本化方案后，逐项模拟处理并把核验结果反馈给模型 | 没有真实执行器或模型执行工具 |
| 跨盘迁移、页面文件、休眠、驱动与系统组件维护 | 未提供专门调优或迁移流程 | 未实现相关模拟动作 | 未实现 |

v0.4 另外完成常用任务首页、摘要启动、服务端分页与搜索、跨页选择及旧签名拒绝。独立基础检查入口移除，工具能力保留。

已经建立的工程基础包括：面向普通用户的中文主流程与按需明细；保护与个人选择优先的建议分组；完整缓存根默认选择；冻结计划、版本绑定和范围验证；本机 HTTP 的来源保护；Windows DPAPI 与服务来源绑定；自动化测试和本机打包验收流程。

已实现不表示所有机器、所有软件或所有 Windows 入口均已验证。每次发布的确切测试结果和限制应记录在对应提交的验收材料中，不用本路线图里的描述替代实测证据。

## 下一步

### 当前最高优先级：LLM 驱动的调查与协作循环

按 2026-11-02 最新方向，[智能体架构提案](AGENT_ARCHITECTURE.md)成为下一阶段演进依据：先建立任务/会话状态和可继续调查的工具循环，再连接用户反馈、结构化计划与统一动作记录。常见缓存规则作为调查工具和经验，不以扩充固定清理表作为主线。模拟和真实后端拟共享动作生命周期，但模拟也要覆盖失败、部分成功与中断；真实后端仍未实现。

v0.3 已完成第一条有界任务流程和新任务的逐项模拟记录。接下来优先验证真实模型兼容与实际任务质量、内容/应用身份调查工具、预算与大目录体验；继续完善当前 UI，不把第一条流程等同于完整通用整理能力。

以下体验、真实执行和发布工作继续有效，按上述主线调整依赖顺序；不能跳过任务循环，仅增加更多规则后宣称已经完成智能体化。

### 1. 完善普通用户体验并稳定当前版本

- 用真实使用任务检查“开始检查 → 建议 → 确认 → 记录”的理解成本，确保主 CTA 清晰、个人选择独立、影响说明及时可见。
- 检验空结果、取消、扫描不完整、模型不可用、模型覆盖不足和旧快照等状态，不能把它们显示成全量成功。
- 继续扩展经过验证的应用知识和正向证据，使非个人建议更具体；不以降低保护门槛增加推荐数量。
- 保证真实磁盘空闲量、逻辑体积、进程工作集和模拟体积始终分别表达。
- 每次代码修改同步设计决策、契约和针对性测试，稳定后再构建并验收最终 Windows 产物。

### 2. 设计独立的受限真实执行器

当前尚未实现，不能通过配置开启。进入实现前先确定：

- 哪一类经过验证的缓存作为首个有限目标，允许什么动作、哪些状态必须停止。
- 执行前如何检查身份、完整性、占用和过期计划；相关应用仍在活动时如何处理。
- 回收站、同盘隔离、跨盘隔离与永久删除各自的授权、空间计量和恢复语义。同盘隔离不算释放空间，回收站未清空也不能算真正回收。
- 跨盘复制后的校验、源文件删除时机、目标空间不足、执行中断与可恢复清单。
- 每个条目的真实结果、失败原因、已处理范围和事后空间核验，不能只检查命令退出码。
- 限定权限与失败注入验收。真实恢复测试应在专用测试数据上完成，不把用户资料当作测试夹具。

只有这些条件具备并通过隔离环境及 Windows 端到端验证后，才安排单独的真实执行测试版本；普通开发版继续保持模拟边界。

### 3. 完善持续发布与隐私检查

- 保持源码与本机 `userdata`、运行数据库、模型设置和原始验收数据分离。
- 提交前检查私人路径、凭据和大体积生成物；发布前检查包内内容与对应源码版本。
- 保留必要的构建散列、测试状态和已知限制，形成可复现发布步骤。
- 设计可预览、可脱敏的诊断导出，而不是直接上传运行目录。

## 未来方向

### 浏览器隐私适配器

按浏览器和数据类型分别设计，不把普通缓存、Cookie、离线站点存储、历史、下载记录、自动填充和密码混成一个按钮。需要明确退出登录、离线数据损失、会话恢复和同步传播的影响。采集、模拟、真实执行分别验收；当前没有真实隐私清理能力。

### 正规软件卸载

逐项识别支持的卸载入口、共享组件和权限需求，提供准确的影响说明与结果检查。安装包留存不等于完整回滚能力；Store 应用支持应单独声明。当前只有注册信息盘点和模拟记录。

### 启动项、服务与进程控制

逐步补足启动来源、实际启用状态、角色、依赖和未保存工作证据。真实控制必须通过专门适配器，区分临时停止、下次启动行为及恢复条件。第三方、高内存或旧版本不构成单独的停用依据。

### 跨盘整理与缓存位置迁移

为受支持工具使用官方设置，保留配置备份和回滚，并验证新进程的实际缓存位置。配置已保存、旧程序仍用旧环境和已有文件是否迁移需要分开解释。不能泛化为整体迁移 AppData 或所有系统临时目录。

### 扩展模型覆盖与增量检查

有实际需求后再设计分批建议、成本预算、缓存失效和增量扫描。模型建议应绑定库存版本，覆盖不足必须持续可见；默认不增加私人内容外发，也不让模型获得任意执行能力。

### 系统调优与定时自动化

页面文件、休眠、驱动、恢复材料和系统组件维护暂不纳入通用清理动作。若未来开展，必须单独建立官方流程、重启后验证和恢复设计。定时检查、提醒、隔离保留期与自动永久删除也需要分别授权与实现，不因为有了调度器就默认具备无人值守清理能力。
