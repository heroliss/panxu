## 方向更新：围绕 LLM 的任务循环

2026-11-02 按用户最新讨论，将下一阶段主方向调整为 **LLM 驱动的整理智能体**。LLM 根据需求决定如何调查、提出计划、解释取舍，并根据用户选择和工具结果继续工作；程序提供可靠事实、经验、操作能力、会话支持和针对任务的 UI。常见清理规则作为可调用的经验与工具继续保留。

详见 [智能体架构提案](AGENT_ARCHITECTURE.md)。下文的固定扫描入口、推荐规则和工具限制同时描述当前 v0.2.0 实现，不能视为未来智能体能力的永久上限。下一阶段优先补充“取得新证据并继续”的能力，避免证据不足就只能让用户自行判断。身份、用户已明确的保留意愿、实际权限、外发范围和结果真实性仍需由程序落实。

历史上 v0.3.0 先实现9种调查/方案工具的持久任务循环。当前已有22个任务工具、18类版本1.3.0指导、结构化问答、用户直接发起的模拟处理与可读开发面板；v0.9 增加独立共享偏好与实时公开回复，不扩大工具或动作权限。独立基础检查入口在 v0.4 移除；下面标明旧版本的规则和顾问预算保留作历史与兼容说明，不用来概括当前主任务能力。

## v0.16：信息按需取得，倾向与后果分开表达

统一所有分析入口的取信息方式。首个请求只传目标、范围边界和必要任务状态，不预装`initial_objects`，不按目标大小分别采用全量或采样。单项、勾选项、筛选集合与目录目标都由LLM通过现有工具决定需要查看多少；工具取得的背景知识不扩大处理范围。此决定更新历史首包样本策略，而不是取消确定的目标、用户选择或可操作身份。

本机完整task/facts与模型输入是两个层次。宿主发送轻量事实索引，按引用回读原内容、原时间和范围；重复观察与记账回显、明确重复的角色/时间壳和可确定空字段从wire投影省略。原生工具结果和调用配对继续保真，有意义的未知、0、false、部分覆盖及分页/身份引用不能因“精简”被抹掉。未随首包发送不等于不存在、尚未采集或允许自动补扫；压缩也不删除持久原文、重写用户意图或私有协议续接。见D048。

## v0.14：统一阅读与操作流程，保持对象和动作的区别

后台、服务、启动项与软件任务采用建议清单/全部项目，文件继续建议/已扫描目录；共享选择、评分、来源和确认流程。全部只指本次任务范围，不是全机内容或所有后台知识。建议视图不把未知条目伪装为AI判断，全部视图允许阅读尚未分析、未评分、跳过与旧建议的真实状态。库存选择表达分析意图，任务结果选择才表达处理意图。

文件允许目录继承及子项例外，后台采用独立ID与具体动作，不以程序路径或名字合并。例如同一exe的两个进程各有身份，停止服务、关闭启动项、结束进程和卸载也各有不同影响。确认按冻结action分组，继续核对签名、保护、来源范围及500批次；服务停止不更改启动方式。共享UI不意味着共享所有文件树语义，更不新增真实执行能力。详见D045。

用途、建议、原因和影响直接显示，使用标签、底色与排版区别主次；模型来源和低频技术细节仍可按需。无模型用途时只给带来源的本机类型说明或未知，缺分不自动等于没分析，旧失效不冒充新判断。操作按钮使用具体动作名，统一全局模式提示保留simulation-only真实边界；确认与结果仍区分记录成功、未核实与真实系统状态，实际释放始终为0。详见D046。

## v0.13：留出形成结论的预算，公开状态可回看

调查不应耗尽全部额度才尝试评分。每轮仍最多6次模型请求、12次工具调用，通常前4次调查、后2次收束；临近工具预算或输出失败时更早切到评分/方案/结论/问题的有限工具集，最后只允许结论或必要问题。模型每次最多6项建议，宿主历史30项与手选500目标保持各自合同。输出上限或参数不完整时最多用现有剩余轮次进行一次持久事实收束，不重新采集、不执行半包，也不把未覆盖范围说成完成。

响应计量区分SSE包装、事件/帧、文本、完整native对象、规范化对象与工具参数语义；预算集中维护，UTF-8和Unicode转义不混算。原生工具续接保留在内存，不能为省预算丢掉协议需要的思考字段，仍不向用户或开发日志公开。旧trace只有`response_budget`不能定位具体触发上限，ASCII膨胀的`invalid_response`及普通正文局部结果误用分别处理；离线夹具可证明机制，不能据此宣布原真实请求已查明每个细节。取舍见D042。

“最近动态”展示已收到的公开状态，默认3条，短时窗口中最多8条并可展开回看当前会话最近32条；每窗口至多8任务，实时连接仍最多4个。4秒用于有界阅读保留，状态仍立即更新，错误优先；它不是后台延迟或每个状态保证展示4秒。标签只表示公开接收/连接事实，工具请求已收到不表示执行成功。浏览器观察时间不冒充任务发生时间；活动缓存与持久公开回复、事实及执行收据分开。取舍见D043。

主清单保留短结论、首条重要留意、评分和操作；所有重点、其余提醒、范围与来源仍在分析详情。动态可回看不等于将日志铺满主线，也不扩大处理权限。最终真实账户与产物验证须单独记录，当前不据离线通过宣称云端任务已经完成。

呈现长度与输出有效性分开：主清单最多160字预览，完整被接受结论仍存储并在详情阅读。工具摘要上限继续为propose_plan600字/present_findings1000字，不因briefing存在而额外降为160；模块每条160及其他限制不变。约80字是短文案指导，不是拒收合法结论的交叉字段规则；评分或事实不能因视觉摘要长度而失去有效性。修正依据与验收见D044。

## v0.12：把确定事实交给程序，让常用信息直接可读

独立“查找重复文件”不要求模型。用户明确指定目录后，本地job先按大小排除不同长度文件，再读取候选完整内容计算SHA-256；不追加逐字节比较。Windows通常不提供一个为每个普通文件预存并维护的通用SHA-256，本轮不以名称、日期、文件ID或签名代替内容哈希。相同大小与哈希是很强的实践证据，仍不是无碰撞的数学证明。

程序与LLM分工延续原方向：程序计算可确定的大小、身份与哈希，模型可另行解释用途、保留位置和引用风险。独立查重结果只读，不发布主库存，不补造评分或清理计划，不自动选定保留/删除副本；这不是回到固定清理规则。硬链接单独呈现为共享实体，保护/项目/凭据/链接/云占位跳过，变化、取消、权限和预算缺口明确报告。逻辑重复体积不能直接等同实际可回收量。

主流程保留评分、对象、影响与下一步操作等常用信息，减少多层`details`。完整公开回复、摘要、模块和来源进入“分析详情”；范围、工作量与事件进入“调查过程”，指导/事实按需读取；“调整要求”独立承接草稿。左上返回沿当前页面关系回到来源，任务与勾选保留；文件详情等必要信息仍可进入。减少展开操作不等于删除解释、来源或安全边界，也不改变目录选择、执行确认、F12面板与模拟语义。独立查重和新页面的实际验收仍须分别记录。取舍见D040–D041。

## v0.11：评分清单、明确勾选与分层通信

调查结果先给短结论和清理倾向，主要工作区用评分清单承接下一步；注意事项、检查范围、来源和长解释按需展开。模块化`briefing`不重复逐项理由，旧长摘要保留全文。模型公开正文是可读文字，任务另存最近一条被接受的公开回复，在重开或重启后可读；实时片段、持久回复、任务摘要及执行结果分别表示各自事实。

两种视图继续存在：建议视图突出实际分析项；目录视图呈现已观察的结构、继承状态及未评分项。任务清单能筛选1–5分、跳过、暂不建议和未评分，分类选择覆盖任务内完整筛选集合，不能只查已显示的50行。自动初选只取本来源任务的合格高分，默认包含4分且可关闭，直接分析优先；低分、具体未知/跳过与保留边界不被上层高分吞入。自动初选不覆盖后续手工调整，最终授权来自用户核对后的勾选。

目录勾选使用正负规则：选父目录、取消子目录、再选其中一个文件，最后只将更具体的那个文件重新纳入。父目录有例外时呈现部分选中，宿主编译成具体文件或完整子目录，不删除包含例外的父容器。未知、跳过和低分也可明确手选；这种`user_direct`选择能覆盖本任务先前的临时保留意愿，却不能绕过真正保护、动作支持、当前身份、范围或目录完整性。仅浏览与编译不补扫磁盘。

选择绑定来源任务、清单/评分revision、独立selection_revision及全部正负ID的签名，来源任务的已知集合之外不会混入其他任务对象。每批最多500个去重目标，完整总数和未纳入部分持续可见，需要明确分批；目录目标不等于单个物理文件。用户确认具体批次后才模拟执行，暂停/继续/取消在条目提交间生效，取消保留已提交结果并区分未处理项。没有真实执行器，实际释放量仍为0。详见D039。

宿主发送给模型的事实使用紧凑缩进文本，保留类型含义、引用、范围、未知及局部共同事实；普通公开正文无需JSON。类型化工具定义与参数、厂商外层协议及私有续接仍按各自协议处理，宿主本机持久数据也继续结构化保存。初始上下文只含有说明的小样本，完整对象与指导按需查询；模型自己决定调查深度，而不是程序无目的采集所有细节。输入收益按模型可见文本/schema与实际usage分别核对，不将HTTP压缩当成token收益。详见D038。

## v0.9 的连接与实时反馈

设置需要回答两个不同问题：“有没有保存”与“服务能否完成工具往返”。有效设置和密钥先保存，固定数据的非流式测试后执行；测试失败不撤销保存，也不清空表单。保存失败则明确说明未保存，等待期间新输入的密钥草稿不被旧成功响应清掉。服务来源绑定和 DPAPI 不变，不为减少操作而静默跨厂商复用密钥。各提供方的模型、思考和工具选择约束见 [官方来源与探测政策](PROVIDER_SOURCES_V090.md)，不从预设或本机夹具推断真实账户已兼容。

整理偏好是常用设置，不再埋在高级连接中。它对所有模型共用、独立保存，只在后续分析中使用；保存不发模型请求，也不偷偷改变已有方案。连接和偏好只接纳各自字段的响应，晚到的数据不能覆盖另一部分新设置。偏好表达用户意愿，不增加执行权限或取消既有保护。

四种模型协议分别解析真实 SSE，再通过本地 SSE 向任务区与开发面板提供累计公开文本；普通界面只呈现公开文字和必要的接收状态，不增加传输按钮。完整工具调用仍经过原有验证和任务运行时，未闭合参数只有等待提示，不能展示成已确认建议、问题或动作。流式是传输方式，不是第五种协议；用户可在高级连接关闭，连接探测继续使用非流式。

文字追赶以临界阻尼弹簧控制 Unicode grapheme 游标，正常追加不倒退；帧时间、积压量有界，最终接收完快速收敛到确切内容。非前缀修订立即替换错误旧文，不为保留动画维持失实内容。减少动画、隐藏窗口或不支持安全分段时直接显示已收到原文。断连保留正文并标未完成，取消或换任务清空；本轮模型回复接收完不是任务或清理完成。

本地通道按任务共享、有连接上限；最后订阅离开即关闭，隐藏窗口暂停并在恢复时取最新快照。进程标识、快照序号及连接代际防止旧包覆盖。短暂中断提示重连，连续错误后停止自动尝试，不能一直忙碌或伪造成功；无 EventSource 才使用有界 GET 兜底。公开快照只在内存，不代替持久事实、方案和执行收据。

开发面板的实时公开回复区与历史记录分开更新，显示跟随面板/窗口可见性和分类选择，与后端采集开关独立；主区及已展开历史不随文字重绘。连接元数据明确标为程序内部信息：外层 `provider` 是服务商标签，不是 API 角色；完整诊断中的 `payload` 才是实际请求/回复。角色正文、系统指令和工具结果继续按协议解释，不改写真实 wire body，也不显示内部思考、签名或凭据。

本轮原生窗口实际核对保存/测试反馈、独立偏好、主区与开发面板的真实增量、跨导航和采集关闭时的实时显示，以及中断保留正文、继续完成和列表图标。取消、四协议错误与减少动画等继续按单元或最终 EXE HTTP 的明确范围理解，不能都标作原生点击通过。确切证据集中见[发布记录](RELEASES.md)；本机夹具验收不代表真实云端与所有账户兼容。

## v0.8 候选的信息呈现与证据边界

普通工作区延续少量意图入口、一次一个问题、一个主要下一步与按需说明。完整路径、历史事实和技术通信不进入默认主层。F12 开发面板独立于主任务和导航，默认关闭，采集与实时显示继续分别控制；主题默认跟随系统，手动选择保持不变。

开发记录首先帮助读者理解“谁说了什么”，不要求先读协议 JSON。请求/回复按角色和正文展示，公开沟通调用中的结论、问题、选项、建议原因与影响直接可读；系统提示、任务上下文、历史事实、工具定义/参数/结果、技能与用量各有按需详情，原始已脱敏 JSON 位于深层且懒加载。四协议统一解释实际 trace 外层封装，未知结构和采集/显示截断如实标记，不补造内容、不显示私有推理或签名。

主表单和未变记录的 DOM 不随轮询重绘。面板展开或滚动阅读时暂存新内容，分类过滤使用当前展示批次，不用最后收到的响应偷换阅读对象。图标也不阻塞列表：只读本地资源、异步缓存、不可用时使用类型图标。图标不作为发布者或安全认证，不参与保护与动作授权，不向 LLM 上传图片。

两项新增工具负责补充可核查的有限事实：`collect_system_configuration(section='memory_power')` 只读固定的内存提交、活动分页与配置、休眠能力等；`inspect_volume(scope_id)` 只查当前任务已有位置所在本地卷的容量、用户可用空间和当前用户回收站统计。结果带来源、采集时间、预算、部分状态与警告，`actions: []`；不创建目录目标、不授权遍历卷或更改系统，未知状态不得填零。它们不能证明磁盘健康、文件可恢复或最优配置。

17类指导是按需加载的版本化经验；指导版本 `1.1.0` 与随元数据指纹变化的目录版本分开。新增浏览器隐私、云占位、虚拟盘、游戏开发、恢复材料和磁盘异常等说明，不等于已经采集相应私有数据或实现清理动作。当前仍没有真实删除/迁移/卸载/调优、SMART/温度/固件/历史事件和完整恢复验证。

## 面向谁，以及替用户承担什么

盘序面向希望整理 Windows 11 空间与后台、但不熟悉系统目录和程序依赖的普通用户。用户不应先学习一堆技术字段，再自己判断每个缓存、服务和启动项的作用。

产品应尽量直接说明“它是什么、建议怎么做、为什么、会有什么影响”。对非个人内容，规则和模型负责完成有依据的判断；证据不足时明确指出缺口，而不是假装已确认安全。个人下载、创建或用途未知的文件，模型可以解释和提供去留建议，最终是否处理仍由用户选择。

这里的“建议处理”不等于已经执行，也不等于没有副作用。界面必须把建议、计划、执行结果和恢复能力分别表达清楚。

## 主流程与渐进披露

v0.4 默认主流程为：**表达目标与范围 → 模型按需调查 → 审阅或调整方案 → 确认处理与核验 → 继续或结束**。

- 首页呈现用户目标与一个文件夹范围，主要行动为“开始分析”。模型在当前范围按需选择调查工具。不要默认遍历全部磁盘，不以开发样例冒充本机结果。
- 任务先呈现当前结论与少量方案卡片，明确动作、原因和个人选择要求。缓存经验和规则仍作为工具供模型调查，独立基础检查不再占用主入口。
- 同一阶段只有一个主要 CTA。结果页的主要动作应围绕当前建议批次；目录选择、重复校验、技术明细和模型设置作为次级入口。
- 默认卡片说明具体用途，例如 Python 下载缓存、图形着色器缓存、某应用的开机启动功能，而不是只显示“低风险”或“建议处理”这样的类别名。
- 原因与影响放在用户容易看到的位置；路径、来源、身份签名、预算、计量和工具追踪等技术依据按需展开。
- “我的文件”和“后台与软件”的完整清单供需要精细控制的人使用。不能要求所有新手先看懂原始表格，才有办法完成主流程。
- 推荐缓存优先以经过完整核查的目录根作为处理单位。已被该根覆盖的子项不重复默认勾选，仍保留推荐身份和明细，避免几千个叶子文件淹没界面与计划预算。

产品界面按正式应用设计。开发阶段的模拟状态用统一全局提示持续可识别，操作名保持自然；不能因去掉逐按钮前缀而隐藏当前没有真实执行器的事实。结果表达内部记录和核验状态，不把“已完成”写成真实文件或系统已改变。具体呈现以D046为准。

## 当前 v0.2.0 的建议规则

判断的优先级是：**保护与能力边界 → 本机证据 → 个人决定权 → 模型建议 → 默认选择**。

1. 系统、凭据、用户保护规则、没有支持动作的项目，以及已经处理的模拟条目，不能被模型重新开放。
2. 缓存默认推荐必须来自采集器验证的受管位置与可再生成性证据。当前实现使用 `verified_cache` 和 `decision_context`；目录还需要完整子树检查。仅凭名字含 cache、Temp，或路径拼出了 AppData 字样，不构成证据。
3. 下载、创建或用途未知的用户文件保持个人选择。模型的理由、置信表达和自定义要求都不能取消 `needs_user_choice`。
4. 后台或软件只有在本机有充分的正向证据，并且模型明确提出相应建议后，才可能进入推荐。高内存、旧时间、第三方厂商或旧版本号本身都不证明无用。
5. 模型可以使本地缓存推荐变得更保守；占用、链接、扫描不完整等限制不能靠一个泛化的证据标记重新放行。

原始库存字段与 `advice` 分离。建议改变不应悄悄改写原始用途、风险、允许动作或系统状态。

## 当前 v0.2.0 的处理契约

当前已实现的程序化处理流程为：

**采集 → 归一化库存 → 保护与证据判断 → 建议 → 冻结计划 → 再验证 → 受控动作 → 结果核验 → 记录。**

- 采集器负责有限范围的文件元数据、Windows 注册信息和运行快照，不把文件名或扫描内容当指令。
- 规则层负责硬保护、个人选择、动作能力、证据有效性和计量，模型不能修改这些边界。
- LLM 负责用途解释、非个人内容建议、取舍与影响说明。结构化输出必须通过 ID、动作、范围和字段验证，不能从自然语言里抽取一个“删除”就当成授权。
- 计划绑定库存版本与具体项目。系统状态变化、路径身份变化或扫描不完整时应重新检查，而不是沿用旧快照。
- 动作使用有限的类型，例如文件处理、启动项调整、服务控制、进程停止与正规卸载。动作类型的存在不代表真实执行器已经实现。
- 执行器、授权、核验和恢复协议应由程序掌握。模型不能批准计划，不能执行任意 shell，不能读额外文件或绕开执行策略。

## 当前实现与开发覆盖层

当前构建可以读取真实库存，但**所有处理动作仅写入本地 SQLite 模拟覆盖层**。没有真实删除、移动、停止进程、控制服务、禁用启动项或卸载程序的执行器，也没有可开启真实执行的隐藏开关。

冻结计划、保护检查、模拟执行、撤销和记录已用于验证产品流程与策略。记录里的撤销只还原工具内部状态，不能解释成已经具备真实文件恢复能力。模拟处理后的实际释放量始终为 0。

空间展示分别使用以下概念：

- 真实磁盘空闲量：只读查询当前磁盘，可能受到其他程序同时写入的影响。
- 文件逻辑体积：用于理解项目大小，不保证与实际占用、可回收量一致。
- 分配空间与硬链接：能取得的证据单独展示，未知时不编造精确值。
- 进程工作集：运行快照，可能包含共享页，不等于停止后能释放同等物理内存。
- 模拟体积：仅表示本地记录中的处理范围，不能与真实空闲量相加或宣称已经释放。

## 现有采集、去重与记录

文件扫描有目录深度、条目数和任务预算，不跟随重解析点，保守保护项目、凭据及系统内容。用户文件目录由用户明确选择；不完整目录不能作为整组处理目标。

Windows 采集覆盖当前实现支持的 Run 注册项、启动文件夹、服务、进程和传统桌面卸载注册项。它不是所有自启动位置、所有 Store 应用、完整服务依赖图或实时文件锁的审计。Run 注册项也不能单独证明任务管理器中的实际启用状态。

重复校验只针对明确选中的文件，在预算内读取字节计算 SHA-256，并检查快照变化。普通盘点和模型上下文不读取文件正文；重复校验是本地哈希这一明确的例外，不会把字节内容发送给模型。硬链接另作解释；内容相同不等于可以自动删除其中一个副本。

本地记录包含计划、模拟处理和撤销状态。后台任务与结果有边界，失败或被取消不能伪装成完整检查。未来真实执行结果应继续沿用可核查记录的原则，但不能把现有模拟记录当成真实恢复日志。

## 旧顾问接口的模型预算与数据私有

以下轮次和样本数描述旧顾问接口；当前主任务的工具与四协议能力见上方当前版本段落及实现契约。未配置模型时不联网，不显示成“AI 已完成分析”。旧接口可以通过 Chat Completions 兼容服务取得结构化建议，不代表兼容每家服务商的专有参数。

- 单次结构化推荐最多发送 100 个有代表性的候选。只统计通过验证的建议覆盖，遗漏与失败明确报告，其余保持本地结果。
- 对话解释最多 4 轮、8 次工具调用。模型只能查询本次提供或选中库存的 `list_items`、`inspect_items`、`summarize_inventory`，不能扩展扫描范围。
- 请求有超时、请求体和响应体预算。未知工具、越界 ID、错误动作、额外决策字段或不合格输出被拒绝。
- 默认不发送完整路径，也不发送文件正文、原始证据内容、账号数据库、进程命令行和环境变量。允许的元数据仍可能包含文件名和用途等私人线索，用户启用远程模型前需要理解这一点。
- Windows API Key 使用当前用户 DPAPI 密文保存；非 Windows 仅驻留内存。公共接口不回显密钥，更换服务来源必须明确替换或清除旧密钥。
- 远程接口要求 HTTPS；HTTP 仅限回环服务，拒绝带认证信息的 URL 和重定向。默认不记录模型对话正文；可选开发记录有界保存脱敏后的请求、公开响应和工具往返，不记录内部思考与协议签名。不用异常原文泄露凭据。

自定义模型要求是偏好，不是新的执行权限。提供方的数据留存政策不是本地程序能保证的，应在接入界面解释清楚；默认路径隐藏也不等于“完全没有私人元数据外发”。

## Windows 范围与发布边界

产品目标是 Windows 11 本地桌面使用，通常以普通用户权限运行。Python 标准库构成核心，桌面窗口和部分运行盘点使用相应依赖；桌面 WebView 不可用时可以退回本机浏览器。非 Windows 单测通过不构成跨平台功能支持。

本地 HTTP 服务只监听回环地址，校验 Host、Origin 和修改请求的 CSRF；静态资源采用白名单，不从 CDN 加载应用代码。正式执行能力即使将来引入，也不应让整个应用长期默认提权。

源码、设计、测试夹具和可复现构建脚本可以进入仓库。运行数据库、真实扫描路径、个人截图、原始验证数据、模型配置、密钥及其他用户数据必须留在本机；发布包只带运行所需代码与资源。记录版本、测试结果和构建散列时，应使用不暴露私人路径或内容的证据。

每个发布版本都应能回答：对应哪个提交、运行了哪些验证、哪些能力是只读或模拟、哪些真实行为尚未实现。源码测试通过不自动证明打包后的 Windows 窗口和最终产物通过验收。
