# 盘序设计说明

本文记录 1.0 重写至 2.0 的主要取舍，供后续开发参考。功能和使用方法见 [README](../README.md)。

## 为什么重写

0.x 由 Codex 开发到 0.29，代码约 1 MB Python 加 1 MB JS，围绕「LLM 任务编排」设计：模型决定看哪里、调用工具、提出问题。但执行器始终只是模拟，从未删除过文件，也没有在真实环境里验证过清理效果。复杂度主要花在编排和界面状态上，清理本身的价值很少。

1.0 的方向（2026-11-03 与维护者确认）：

- 技术栈保持 Python + pywebview（WebView2）+ HTML/JS，PyInstaller 打包。
- 删除策略按类别区分：规则已知的系统和应用缓存直接删除；个人文件（大文件、重复文件、用户选择的文件夹）移到回收站；每次操作都记录。
- 1.0 范围：垃圾清理、空间分析、大文件和重复文件、开机启动项和服务。
- AI 采用混合模式：程序掌控流程，明显的情况由规则决定，模型只对规则不认识的文件夹做分类，并且可以对整个文件夹下结论而不必逐个文件询问。

## 前后端通信：pywebview js_api，不用本地 HTTP 服务

0.x 在 127.0.0.1 上开了一个 HTTP 服务。对一个能删除文件的程序，这意味着本机任何进程、以及通过 DNS 重绑定的网页都可能调用删除接口。1.0 改为 pywebview 的 js_api 桥：只暴露一个方法 `Bridge.call(method, params)`，内部分发到 `Backend.m_<method>`，返回值统一为 `{ok, data | error}`。界面由 `ui_bundle.build()` 内联成一个 HTML 字符串，通过 `create_window(html=...)` 加载，不需要文件服务器。

长任务（扫描、清理、AI 分析）在后台线程运行，界面每 300 毫秒轮询一次 `job` 状态。轮询比从 Python 端调用 `evaluate_js` 推送更容易测试，也不会碰到跨线程调用窗口的问题。扫描、写回 AI 结论和修改操作共用互斥，避免首页与单项工具同时替换共享结果。`Bridge` 在读取输入之前取得提交锁，`JobManager.start` 再检查活动任务，两个入口同时点击也只启动一个；查看结果、浏览页面和只读「问 AI」不受影响。这里只拒绝冲突请求，不排队、不做任务编排。

体检在每个阶段完成并发布结果后更新 `progress.completed`。全局 `activity` 状态让顶部进度和当前工具页同步；阶段首次完成时刷新相应页面，最终方案完成后再次刷新评分和共用勾选。不同范围的重新扫描必须等当前任务结束后主动发起，不把上次结果冒充新扫描。未完成或未选择的阶段仍可能显示上次结果，进度条说明这一点。

## 桌面窗口

使用 pywebview 无标题栏窗口和界面内的统一顶栏，按钮仍调用桌面窗口的最小化、最大化、还原和关闭行为；关闭经过原有的清理确认。`windowing.WindowControls` 只操作本程序窗口，可注入假窗口。Windows 保留原生缩放边框和系统菜单样式，拖动使用 pywebview 官方的拖动区域，最大化使用当前屏幕工作区。WinForms 的无边框还原尺寸与补上的原生边框有差异，只在尺寸恰好少掉边框时补回，避免连续还原逐次缩小；键盘吸附或 DPI 变化由系统决定。原生装饰初始化失败时恢复系统标题栏；浏览器预览隐藏窗口按钮。

## 删除的安全边界

| 层 | 位置 | 作用 |
|---|---|---|
| 规则目录 | `junk.validate_catalogue` | 测试中静态检查每条规则的目标都位于已知基础目录之下，且不是基础目录本身 |
| 运行时根目录检查 | `junk.unsafe_root_reason` | 解析出的清理根目录不能是盘符根、不能包含用户文件夹或系统目录；来自 %TEMP% 的根目录必须名为 Temp/tmp |
| 保护策略 | `paths.ProtectionPolicy` | 用户和 AI 选择的路径：受保护子树内的不能删，基础文件夹本身不能删，包含受保护或排除文件夹的上级目录也不能删；对原路径和解析后的真实路径都检查一次 |
| 遍历 | `fsops.walk_files` / `st_is_link` | 不进入名称代理类重解析点（目录联接、符号链接）；OneDrive 云文件的重解析点会正常进入；无法判断的一律当作链接 |
| 回收站 | `winapi.recycle_paths` | SHFileOperationW 带 FOF_ALLOWUNDO 和 FOF_WANTNUKEWARNING：放不进回收站时由 Windows 询问；不带 FOF_SILENT，大文件夹要几分钟时显示 Windows 自己的进度窗口 |
| 回收站里到底有没有 | `fsops.recycle` / `winapi.recycled_since` | 「不在原位置了」不等于「在回收站」：回收站放不下、用户在 Windows 的提示里选了直接删除时，东西是彻底删掉的。每移一批后读这块盘回收站里新出现的 $I 记录（每一项一个，记着原路径），不在里面的算「已直接删除」（`DeleteStats.permanent`），结果、清理结果卡片、「已处理」和操作记录里都这样写，不再说「已移到回收站」。读不了回收站时按原来的方式算 |

文件「年龄」在 Windows 上取修改时间和创建时间中较新的一个，因为从压缩包或安装程序里解出的文件常常带着很旧的修改时间。

**打开和查看**：列表里有路径的地方都有「在资源管理器中显示」（文件夹图标：文件在所在文件夹里选中，文件夹直接打开；已经不在的路径打开离它最近、还在的文件夹）。文件另有「打开」（箭头图标，和在资源管理器里双击一样），但程序、安装包、脚本和快捷方式（`api.RUNS_CODE`，`web/ui.js` 里同一份列表，测试检查两边一致）没有这个按钮，后端也拒绝：对它们来说打开就是运行，磁盘清理工具里点一下不该运行下载文件夹里的旧安装包或来历不明的脚本。

## 空间分析的操作

和资源管理器一样：单击选中一项（列表里的行和占用图里的块同时高亮，右侧卡片显示它是什么、多大、有什么说明，以及「进入 / 打开」「在资源管理器中显示」「问 AI」），双击（或回车）进入文件夹、打开文件；图里块中的小块双击直接进入那一层。以前单击就进入，用户想先看看是什么时就被带走了。单击不能重画页面，否则双击的第二下会落在新的元素上，所以选中只切换样式、替换卡片。占用图是 4:3、高度不超过窗口能放下的范围。

**界面的几个约定**：页面占满窗口宽度——盘序主要是列表和表格，宽了只会让名字和路径放得下（限制行宽是为了长段文字，这里几乎没有）。单行显示的路径放不下时截掉中间、保留开头和最后的文件或文件夹名（`PX.pathText`，和资源管理器的做法一样），完整路径在悬停提示里，复制时也是完整的；确认框里的路径照常完整换行显示。超过 4 秒的后台任务（体检、扫描、AI 分析和复核、查找重复文件、清理）完成时给一句结果，用户已经切到别的页面时带「查看」，盘序不在前台时让任务栏按钮闪烁（`FlashWindowEx`，不抢焦点）。

## 中途关闭或被强行结束

盘序随时可能被关掉、在任务管理器里结束或遇到断电，所以每样留到下次的东西都要经得起「写到一半」：

- **设置、Key、AI 缓存、演练环境状态**：先写临时文件再整体替换（设置和 Key 还先刷到磁盘），留下的只会是旧的或新的完整文件。
- **操作记录**（`oplog`，一行一条）：被打断时可能留下半行。下一次写入前先补上换行，半行不会把新的一条也带坏；读的时候跳过坏行，半个汉字也不会让「操作记录」打不开。
- **会改动文件的操作**（删除、移到回收站、垃圾清理、执行方案）：开始前先记一条「进行中」（打算处理什么），之后每秒记一次进度，结束时用完整的记录替换它。进程被杀掉时，下次打开「操作记录」看到的是「没有完成」、原计划处理的文件和被打断前大约处理到哪里。（实测：删除 2 万个文件时在 2.5 秒杀掉进程，记录显示约 1.37 万项，实际删了 1.7 万。）
- **关闭窗口**：清理进行中时先问一句；确定关闭就让它处理完当前这个文件、写好记录再退出（最多等 8 秒），而不是在半路被直接切断（任务线程会随进程一起结束）。只读的扫描和分析直接关闭。
- **AI**：每收到一次回答就存进缓存，中途关闭或「停止」也不会白花已经花掉的额度。
- 单个文件的删除和移到回收站本身由系统保证要么完成要么没做；开机启动和服务的修改是单次写入，改完立即记录原值。

压力测试顺便发现：删除前去掉「被另一个选中文件夹包含的路径」、删除后更新各页面结果，原来都是两两比较，2 万个文件要几亿次比较，界面会卡住好几分钟。现在逐级查上层文件夹（`paths.within_any`），代价只和目录深度有关。

## 空间扫描

扫描器只为目录建立节点（`__slots__` 对象），文件只累加到所在目录；另外保留全盘最大的 5000 个文件，供大文件页面使用。打开某个目录时，它自己的文件再实时列一次。这样一块有几百万个文件的磁盘也只占几十 MB 内存。

多个线程从同一个队列取目录。子节点总是在父节点之后追加到列表，所以扫描结束后倒序遍历一次就能把大小汇总到上层，不需要加锁。在 Windows 上 `DirEntry.stat()` 的结果来自 FindFirstFile，本身不额外访问磁盘。

垃圾清理、空间分析、大文件、我的文件、重复副本的待处理大小和删除结果统一按本机磁盘占用统计。普通文件沿用文件长度；Windows 上标记为稀疏或压缩的文件通过 `GetCompressedFileSizeW` 查询实际分配的字节，不读取文件内容。`logical_size` 另存标称长度，二者不同时在详情显示；哈希、重复文件分组和文件是否改变的检查仍使用标称长度。云端占位文件的本机占用记为零，不触发下载。

已知限制：普通文件不计簇尾空隙，硬链接在空间树里仍按每个路径累计（WinSxS 的说明里已经提示），文件系统元数据也不在统计内。无法查询稀疏或压缩文件占用时回退到标称长度，因此显示与实际可用空间变化仍可能有差异。回收站中的文件仍占空间，不算已释放。

回收站规则的扫描大小来自 Windows Shell，界面注明它是估算，可能包含标称长度；清空回收站后的「已释放」按各磁盘可用空间的变化累计，不把 Shell 的估算大小当作释放量。

## AI 分析流程

`analyst.Analyst.analyze_space` 由程序控制，模型只负责分类：

1. 内置规则先判断明显的情况（系统、程序、个人文件夹、已知缓存），不发给模型。
2. 结构性的文件夹（C:\、用户文件夹、AppData\Local 等）自动展开，看它们的子文件夹。
3. 每个分支上第一个规则不认识的文件夹生成一份摘要：匿名化的路径、大小、文件数、修改时间、主要子文件夹、文件类型分布、最大的几个文件名，以及程序查到的线索（找不到对应的程序、旁边有更新的版本、很久没改过）。不上传文件内容。
4. 模型对每个文件夹回答：可以清理、建议保留、需要确认，或者「内容混合，请看这几个子文件夹」。只有最后一种会在下一轮细看（`descend`，这是唯一的「再看一点」），总请求数有上限（默认 8 次，每次最多 12 个）。一次分析从大到小发 `Analyst.capacity` 个（请求上限减去四分之一、留给细看子文件夹，默认 6 × 12 = 72 个），剩下的数量和大小随结果返回，界面上「继续分析下一批」：看过的从缓存直接给出，只问新的。请求用完或失败而没看到的文件夹（包括 AI 点名要细看的子文件夹）也算在剩下的里面；下一次运行时，缓存里「内容混合」的答案会把这些子文件夹重新排进来（`Analyst.followups`），所以确认框里的数字和要不要配置模型都按它们算。
5. 结果缓存 30 天，文件夹大小变化不大时重新分析不消耗额度。

没有大小下限（1.1 早期默认 500 MB，后来 200 MB，2026-11-05 起默认「不限」，旧设置里写入时的默认值迁移一次，用户自己选过的值保留）。原来的考虑是省额度和时间：太小的文件夹清掉也省不出空间，每个要发的文件夹还要读一遍做摘要；真实电脑上 0.3 GB 的 E:\Temp 因此从没被看过，内容少的文件夹也有残留、日志之类值得说明的东西。现在额度由「从大到小、一次一批」控制：小文件夹排在后面，不会挤掉大的，也不会一次把请求用完；空文件夹不发（不占空间，也没有可判断的内容）。AI 点名要细看的子文件夹也不再要求 50 MB 以上（`child_floor`），只要不空。「设置 > AI 分析 > 最小文件夹」仍可以设一个下限，只看大的。每个磁盘最上层的 Temp / Tmp 由知识库认得（`*:\Temp`，在演练环境里也匹配模拟的 C:\ D:\），不发给模型，作为「盘序认得」的建议列出（`Analyst.known_cleanable`）——只是说明不是清理规则：有人也会把东西临时放在那里，所以不自动勾选；达到 10 MB 时进入体检的「其他临时目录」，4 分，由用户确认后移到回收站。几个具体选择：

- `knowledge.Knowledge.ai_role` 把路径分成 skip（已知，不问）、descend（结构性文件夹，展开看子文件夹）和 ask（发给模型）。个人文件夹属于 skip，既节省额度，也不把个人目录名发出去。
- 每个请求要求模型只返回一个 JSON 对象。支持时开启 JSON 模式，服务端返回 400 时自动关闭重试；解析失败会带提示重试一次。
- 模型返回的 verdict 不在允许范围内时一律当作「需要你确认」；`look_into` 只接受摘要里真实存在的子文件夹名。
- 401/402/403/404 这类配置错误会立即停止，不继续消耗请求预算。
- 结果按匿名化后的路径缓存 30 天；文件夹大小变化超过一倍时缓存失效。

AI 建议默认移到回收站；勾选的初始状态只包括「可清理」且把握不低于 75% 的项目。

**模型看到什么由程序决定，不让模型自己调工具。** 模型只做判断，它能看到的东西都是程序事先查好、写成短句一起发过去的：查什么、读哪个文件、发出去什么，都在代码里固定、可测试、可以匿名化，费用也固定。唯一的「模型要更多」是空间分析的 `descend`：它只能从摘要里给出的子文件夹里挑，而且有请求上限。不做模型主导的工具循环（AGENTS.md），原因：模型不能扩大要读、要发的范围；结果可复现；不会因为一次判断查个没完。2026-11-05 维护者问过要不要让模型从一张固定清单里主动要信息，按这里的建议维持现状：缺的信息就由程序补成事实；对单独一项想看得更深时用「问 AI」，它拿到的上下文比批量判断更多（启动项、服务、应用也带上 `itemfacts` 的事实，提示词要求以这些事实为准）。

各处现在给模型的信息：

| 分析 | 发送的信息 | 程序查好的事实 |
|---|---|---|
| 空间分析的文件夹 | 匿名路径、大小、文件数、修改时间、最大的子文件夹和文件、类型分布 | 对应的已安装程序（`installed_app`）、旁边是否有更新版本、多久没改过 |
| 我的文件 | 文件名、匿名文件夹、大小、日期、分组、盘序的备注；用户允许时加文档开头 | 是否和另一份内容完全相同（备注里） |
| 大文件 | 文件名、匿名文件夹、大小、日期、类型（分组「大文件」）；只限扫描列出的、可以在这里删除的文件，按请求上限能发多少发多少（`large_files_for_ai`） | 知识库对所在位置的说明（备注里） |
| 重复文件 | 每份副本的匿名路径、日期 | 在程序 / 工程里还是旁边（`place`）、工程里有没有文件提到它（`refs`） |
| 开机启动项、服务 | 名称、命令行（匿名）、发布者、描述 | `itemfacts`：是否正在运行、开机怎么启动、是哪个应用的一部分（应用包或同一文件夹，发布者从应用包清单读出）、这个应用现在是否开着 |
| 已安装的应用 | 名称、发布者、版本、类型、大小、安装日期 | 最近运行时间（需要管理员）、现在是否开着（`open_now`） |

真实电脑上的例子：ChatGPT 和 Claude 应用各带一个服务（`CodexSandboxService.OpenAI.Codex`、`CoworkVMService`），模型只看到名字和路径时，有时判「可以禁用」，理由却写着「禁用后应用可能无法正常运行」。现在它们带着「程序在应用「Claude」自己的应用包里，是这个应用的一部分（发布者 Anthropic, PBC）」「这个应用现在正开着」一起发，提示词也写明属于应用的服务、用户正开着的应用的服务判「建议保留」；真实模型（DeepSeek）在演练环境里对同样的服务判「建议保留」，纯更新器仍是「建议禁用」。另有两道程序的检查：模型的理由说禁用会让程序无法正常运行、功能受限时，「可以禁用」改成「建议保留」（`analyst.says_it_breaks`，「不影响使用」不算）；现在正开着的程序，不管缓存里的旧答案怎么说，都不显示「建议卸载」。改判时界面上注明「盘序改了 AI 的结论」。

## 开机启动项

列出注册表 Run（当前用户、所有用户、32 位）和两个启动文件夹。启用或禁用通过 Explorer 的 StartupApproved 标志完成，和任务管理器的「启动应用」使用同一套开关，原有的 Run 项和快捷方式不会被删除或改动。修改「所有用户」的项目需要管理员权限。以另一个管理员账户提权时，HKCU 属于那个账户，所以当前用户的项目只读。

服务只允许修改第三方服务的启动方式（`sc.exe config`），Windows 和微软的服务只显示。每次修改都在操作记录中保存原来的值，可以撤销。

## 1.1：傻瓜操作 + 详细说明 + 全程 AI 辅助

维护者确认的方向（2026-11-03）：一键体检、自动给出清理方案，同时列出所有清理项，用户可以审查和修改；用户通常只懂自己下载和创建的文件，而自己的文件时间久了也会忘，所以既要帮用户做决策，也要帮用户了解自己的文件。约束不变：程序掌控流程，模型只做分类和解释；个人文件只能由用户勾选后处理，默认进回收站；模型的建议不能扩大处理范围，也不能绕过 `ProtectionPolicy`。

借鉴：Czkawka / FSlint（多种「找垃圾」工具并列）、dupeGuru（文件名模糊匹配、每组保留一份）、BleachBit / winapp2.ini（只挑公认安全的位置手工加规则，不整体导入）、AppDataCleaner（卸载残留）、微软电脑管家（一个大按钮、默认只勾安全项）、LlamaFS（读取内容帮用户理解文件，但盘序只做了解与建议，不自动移动或重命名）。

### 一键体检与清理方案（`checkup.py`）

首页分「检查范围」和「分析选项」。`selected_drives` 保存独立磁盘选择（`null` 兼容旧 `other_drives` 默认值，空列表表示不整盘扫描）；当前用户、公共目录、重定向的常用文件夹及添加的位置始终检查。查重的次级选项 `cross_drive_duplicates` 默认开启，关闭后先按磁盘与大小分组，再读取内容，避免为跨盘候选做无效比对。AI 主开关 `use_ai` 下的 `ai_scopes` 分别控制 space/files/duplicates/startup/apps/services，关闭父项（空间扫描、查重、检查应用与服务）会禁用相关子项但保留选择；未配置模型时给出配置入口。全部选项只控制首页体检，单项工具及主动「问 AI」独立。开始时固定本次选择，旧结果仍显示原范围，改选项只影响下一次。

首页体检后保留总览和统一执行入口，完整方案默认收起；点击分组总览或「查看统一清理方案」可展开审查、调分勾选和排序（只在每个分类内排，分类的位置不变）。各工具的覆盖情况和直达入口集中展示：大文件复用空间扫描；开启「检查应用与服务」时开机与服务算已检查，应用在同时扫描了残留时算已检查，关闭时只覆盖启动项、残留和失效登记；应用页的残留和失效登记复用体检结果（应用元数据也辅助安装包匹配）。垃圾页从 `junk_result` 复用扫描和评分；启动项从 `startup_list` 获取共享 AI 建议，工具页启停同步首页状态。新体检关闭 AI 时清除对应当前结果中的旧 AI 判断，不清除独立工具以前未被覆盖的扫描。

体检按顺序跑已有的工具：垃圾规则 → 所选磁盘及个人位置空间扫描 → 我的文件 → 重复文件（可选跨盘） → 应用与服务（可关闭，只读） → AI（有 Key 且设置允许）→ 生成方案。重定向的常用文件夹和设置中添加的位置也会纳入。空间树用一个没有文件系统路径的「本机磁盘」节点汇总各盘，各节点 ID 在整棵树内唯一；其他账户和排除目录不遍历，系统与程序只统计占用。个人文件和重复文件阶段仍跳过系统、应用数据和受管理的缓存。结果写进 Backend 的共享状态，其他页面直接查看。

个人文件阶段最多 40 万项；首页重复文件阶段最多 40 万个符合大小门槛的候选文件、16 GiB 的哈希读取预算。只按完整内容校验过的结果生成副本建议，不能将快速头尾采样当作重复。达到上限时在首页和工具页明确提示，可选择目录继续完整查找。空间统计也显示无权访问、排除、链接、云端内容等遗漏；这些标记向父节点传播，禁止依据不完整的树自动处理整目录。目录的活动时间同时考虑 Windows 创建时间，复制过来的老文件不会被误当作多年未动。

方案分三组：

- **放心清理**（自动勾选）和 **建议你看看**（不勾选）由**勾选门槛**分开（`settings.checkup.auto_threshold`，0–10 分，默认 5）。每个来源给一项定两件事：它**能不能**被自动勾选（`eligible`，不能时写明 `hold_reason`），以及它的建议清理度；`PlanBuilder.add()` 只勾「能勾、没被阻止、分数达到门槛」的项目，勾了的进放心清理，其余进建议你看看。
  - 设置里三档：**稳妥 ≥ 8 分**、**适中 ≥ 7 分**、**积极 ≥ 5 分**（默认，维护者 2026-11-04 确认：除了用户自己创建或下载的文件和工程，其他东西可以大胆一点；再加上旧版本和卸载残留）。门槛用于已经通过守卫的项目，规则默认开关或 AI 的信心都不能单独决定勾选。0.x / 1.1 早期的 `auto_select: careful` 迁移成 8 分。
  - 不管门槛多低都不会自动勾的底线（`eligible=False`，`PlanBuilder._folder_guards` 等）：个人文件和工程；不在 AppData / ProgramData 或受保护的目录；**仍在安装的程序的整个目录**（用真实模型测出：模型按体积最大的文件判断，会把「大部分是缓存」的程序目录整个判成可清理，而里面还有设置、许可证和模板；名字像缓存的子目录可以）；7 天内有改动的；子目录里有存档、Profile、备份之类名字的；里面有 .exe / .dll 的（可能是程序本身）；不能撤销的操作（清空回收站、Windows.old、DISM、Maven 本地仓库，`NEVER_AUTO_RULES`）；AI 没判「可清理」或把握不到 0.7（`MIN_AI_CONFIDENCE`）；开机启动项。目录只进回收站。
  - 首页的**按分数勾选**（≥ 9 到 ≥ 5 五档 / 全不选）对当前方案即时套用同一条规则，只动能自动勾的项目；「包括我的文件」由用户自己打开（对当前选的档位立刻生效），才会把个人文件按分数一起勾上。被底线挡住的项目永远不被批量勾选，「全不选」则取消所有勾选。高亮的档位跟着实际勾选走：刚点的那档、体检用的门槛，或恰好勾出同样结果的一档；用户手动改过、哪一档都对不上时不高亮，并说明「你已经手动调整过勾选」。点完会提示多勾或取消了几项（两档之间没有项目时说明「勾选没有变化」）。门槛和按分数勾选是同一个概念：设置里定的是每次体检的默认值，首页上是这一次的临时调整。
- 建议你看看还包括：没有 AI 时的启发式（AppData 下 ≥ 500 MB、找不到对应的已安装程序且一年没改 → 可能是卸载残留；旁边有更新版本的同级目录且一年没改 → 可能是旧版本）、我的文件、重复文件、AI 建议禁用的启动项、可以卸载的程序和 AI 建议不必开机自动运行的第三方服务。每类有「全选这一组」和去对应工具页的链接。
- **仅供了解**：hiberfil.sys、pagefile.sys、WinSxS、Docker / WSL、Steam、微信文件等，只说明怎么处理，能操作的附上入口（关闭休眠、打开系统设置、复制命令、打开文件夹）。

一个路径只出现在一项里（先到先得），重复文件组只要有一份已经出现在别处（例如版本组）就整组不提供：两条各自「保留一份」的规则叠加起来可能把所有副本都删掉。启动项建议不包括 `%SystemRoot%` 下的程序（Windows 组件和驱动），模型的建议本身不够。执行时每个路径再过一次 `ProtectionPolicy`，重复文件先确认没被修改过；确认框分别写明永久删除、进回收站和禁用的项目。体检从不发送文件内容。

**建议清理度**：内部保存 0–100，界面显示 **0–10 分**（四舍五入，`checkup.points` / `PX.points`）：8–10 建议清理、5–7 可以考虑、0–4 看你需要。它不是“安全概率”。规则由 `rule_assessment` 按重建成本、近期活动和不可恢复的影响计算，首页与垃圾清理页共用，详见 [规则维护说明](RULES.md)。体积大只影响排序和预计释放量。

AI 目录的「可清理」基础 65，缓存名称特征加 10，半年无新增/修改加 5，上限 85；「需要确认」基础 50。模型把握低于 70% 时最多 40 并禁止自动勾；近期活动最多 40，程序、个人资料、未完整扫描等守卫最多 30。AI 信心用于可信度门槛，不再直接换算为建议分数。启发式基础 50–60，同样经过守卫并下调分数。`assess_ai_dirs` 将相同结果用于空间分析页。

个人文件永不自动勾选：新版或刚下载的安装包降低建议，无法确认版本的安装包也不当作已被替代；下载残片未满 30 天为 70，更久为 90；空文件夹没有空间收益，为 30。ZIP 只有全部文件的大小和 CRC 校验均匹配才给出已验证的 85 分；超过 5000 条目或 128 MiB 内容校验上限、不支持的格式或遇到链接/云端文件时不宣称已验证。文件模型判断可自由调低，单看名字最多加 10，读取用户允许的内容最多加 20，且不能把原本低分的项目提到 75 以上；版本、同名文件夹、年久未动等需要内容确认的线索，模型只看名字不得加分。每项依据最后一行仍说明勾选决策。

**一份勾选，到处一样**（`PX.sel`）：首页方案和各工具页显示的是同一批东西，所以只有一份勾选——垃圾规则按规则 id，单个文件、文件夹和重复副本按路径，启动项按方案项 id。在「垃圾清理」或「我的文件」里勾的，回到首页也是勾着的；工具页只处理本页选中的项目，清理后方案里对应的项目标成「已在「垃圾清理」清理」/「已处理」（`m_junk_clean`、`forget_paths`）。工具页在已有方案时提示这一点，方案的每个分类都有「去「垃圾清理」」这样的入口。左侧导航分成首页、单项工具、记录与设置三段。

**切换页面保持位置**（`app.js` 的 `PX.go`）：每个页面离开时记下滚动位置，回来时回到那里，像浏览器的标签页——在首页和工具页之间来回看细节时不用重新找。页面先画出来、数据加载完再补全，所以恢复的位置会一直保持到内容够长、用户自己滚动或点击、或者 3 秒后为止。三种情况从顶部开始：页面内容在离开期间被换掉了（重新体检、重新扫描，`REPLACES`）；从完成提示的「查看」进入（结果在顶部）；在当前页面上再点一次它在左侧的入口（回到顶部的惯例）。

**可视化**：每个页面先给一张图再给列表——首页三块统计（每组多大、勾了多少）和「空间都在哪里」（每类的放心清理 / 建议你看看）；垃圾清理按组的已选 / 没选；我的文件按类型、按建议清理度分色；应用里占空间最多的程序（半年没用的标成琥珀色）；大文件按类型；开机与服务的启用 / 禁用 / AI 建议禁用；操作记录的累计释放和来源。点图上的一行跳到对应的位置。三组的颜色（`--g-safe` / `--g-review` / `--g-info`）在浅色和深色下都用 dataviz 校验脚本检查过色盲区分度和对比度；分数的三段沿用分数格子的绿 / 琥珀 / 灰。

在真实电脑上测出、已经修正的误报：「多个版本」把任何结尾数字当版本号（应用缓存 data_0…3、字体字重、游戏回放），Documents 里由程序管理的文件夹（企业微信、My Games、Adobe、node_modules）被当成个人文件，只含 node_modules 的项目文件夹被当成空文件夹。现在只认明确的版本标记、只看文档图片音视频压缩包，并跳过缓存、日志、开发目录和这些应用目录（`insights.managed_dir`）。后来又发现：解压在「下载」里、正在使用的免安装程序（Snipaste）的主程序被当成「很久以前下载的安装包」。程序自己的文件夹（有 DLL，或者 .exe 旁边有 platforms、plugins、locales 这类运行时文件夹）现在整个跳过：它的 .exe 不是安装包，里面的大文件、旧文件和空文件夹也不是用户零散的文件（`insights.is_program_dir`）。再后来：一个 Node 项目的 `docs` 里，`delivery_notes.md` 因为旁边有 `delivery_notes_v9.md` 被当成「较旧的版本」，体检的 AI 复核（只发文件名）回答「可以删除」，建议清理度从 35 加到 65，也就是从 4 分变成 7 分。两处一起改：代码项目（有 .git，或 package.json、pyproject.toml、*.sln 这类构建文件，扫描的起点文件夹本身除外）里不再猜版本，也不提供空文件夹，项目文档按项目的版本命名是有意的（`insights.is_project_dir`）；内容不同的旧版本，AI 没看到内容时的「可以删除」不再加分（`with_ai(needs_content=True)`），评分依据里写明「AI 只看了文件名」，提示词也要求这种情况判「需要你看看」。

**应用与服务进入体检**（2026-11-07，维护者希望一次体检生成完整方案）：比起只在首页放入口，把它们放进体检更能回答「这台电脑还能清掉什么」，但两类操作都不能和其他项目一样批量执行，所以只读取和分析，处理方式各自保守：

- 开关 `checkup.apps_services`（默认开），AI 分项 `ai_scopes.apps` / `ai_scopes.services`。体检读取已安装程序（有管理员权限时带 Prefetch 的最近运行时间）和服务列表；AI 只问应用与游戏（运行库和驱动不问），服务只问第三方的，发送的内容和工具页的「AI 解释」相同（`Backend._app_for_ai`、`services_for_ai`），共用 30 天缓存。结果存进 `Backend.app_ai` / `service_ai`，应用页和服务页直接显示；新体检关闭 AI 时清掉旧判断，和启动项一样。
- **可以卸载的程序**（`PlanBuilder.add_apps`，动作 `uninstall`）：AI 建议卸载（正开着的程序已经被 `explain_items` 改成「看你是否需要」），或者运行记录显示一年没运行且占用至少 200 MB（`APP_IDLE_DAYS`、`APP_IDLE_MIN`；大小优先用空间扫描里程序自己文件夹的占用，共用的登记位置不算）。分数：AI 建议且半年没运行 6 分、只有 AI 建议 5 分、只有运行记录 4 分。永不勾选，也不在「执行选中的项目」里：卸载程序会弹出自己的窗口、可能要求重启，必须一个个由用户完成。行里的「卸载…」走应用页同一套确认和「检查是否卸载完成」，卸载完成后 `m_apps_list(fresh)` / `m_app_installed` 把方案里这一项标成「已卸载」。
- **服务改为手动启动**（`PlanBuilder.add_services`，动作 `service`）：只有 AI 建议禁用、仍是「自动」启动的第三方服务；执行时改成「手动」而不是「禁用」——开机不再自动运行，需要它的程序仍能按需启动它，误判的代价小得多。6 分、永不自动勾选，没有管理员权限时标明并挡住；`set_start_type` 记录原值，可在操作记录撤销。工具页修改或撤销时 `_sync_service_item` 同步方案状态。

**排序**（`PX.sortRows` / `PX.sortBar` / `PX.sortHead`）：有表头的列表点表头，没有表头的在列表上方给一排「排序」选项，再点一次反过来。名称默认 A→Z，日期默认最早的在前（清理要找的是很久没动的东西；操作记录例外，最近的在前），数字默认从大到小；空值无论哪个方向都排最后，并列时按第二个键（通常是大小），再按原顺序。分组的列表只在组内排序，组本身的顺序不变（AI 结论、首页的分类、我的文件的类别），因为组表达的是不同的处理方式。

**空间分析的详情卡片**：固定高度，避免下面的占用图跟着跳；不再滚动——标题、路径、事实和按钮总能放下，说明文字用剩下的高度，按整行省略（`fitDetail` 量出能放几行），完整内容在悬停提示里；窄时「在资源管理器中显示」只留图标。

**重复文件的默认范围**和首页体检一致：`checkup.space_roots`（首页选中整盘检查的磁盘，默认全部本地固定磁盘；用户目录、公共文件夹、重定向的常用文件夹和添加的位置，去掉被其他位置包含的）。查找整个磁盘时用体检同样的上限（`checkup.DUP_BOUNDS`），并按 `ordered_roots` 先查个人文件夹；选择具体文件夹时不设上限。用户自己的文件夹（`container_roots`）不会被当成「工程旁边」，即使没有被直接选来查找。

### 我的文件（`insights.py`）

默认尽量覆盖本机的个人文件，按优先级查看：桌面、文档、下载、图片、视频、音乐和设置里的额外位置；当前用户的整个用户目录与公共文件夹；系统盘上其他自建目录；其他本地固定磁盘。重叠的目录只看一次，优先让常用位置在文件数上限之前得到查看。可移动磁盘和网络位置不默认整盘扫描，但已重定向到这些位置的已知文件夹和用户配置的额外路径仍在范围内。是否为固定磁盘由 Windows 的驱动器类型决定，部分通过 USB 连接的 SSD 也会被识别为固定磁盘。

扫描会跳过系统、已安装程序、应用数据和缓存、其他账户、保护策略中的排除目录、链接和云端占位文件。扩大查看范围不改变删除边界：个人文件不自动勾选，只有用户选择后才处理，默认进入回收站，仍经过 `ProtectionPolicy`。整理过程中报告已查看的文件数和文件夹数；达到文件上限时，结果的 `stats.truncated` 和 `stats.limit` 让界面明确提示「本次未扫完」，不把部分结果说成全盘完成。「选择文件夹整理」复用 `pick_folder` 和 `insights_scan(roots=[folder])`，只改变这次整理的范围，取消选择保留已有结果，不写入额外位置设置；「重新整理本机文件」恢复默认范围。

找：已安装程序的安装包（与「已安装的应用」模糊匹配，能指出已装的版本更新）、很久以前的安装包、没下完的文件、已经解压过的压缩包（.zip 在预算内核对全部文件的大小和 CRC；未完整验证时不称为已解压完）、同一文件的多个版本（「(1)」「- 副本」「_最终版」「_v3」……，组内用哈希找出完全相同的副本，每组只提供删除多余的，修改时间相同时保留没有副本标记的那份）、很久没动过的大文件、下载文件夹里的旧文件、空文件夹。照片视频只有带副本标记才算版本；程序文件夹、解压出来的文件夹和代码项目里不找版本。

AI 的结论只能这样改分数（`insights.with_ai`）：「保留」「移到别处」随时可以降低；「可以删除」仅名称判断最多加 10 分，有内容证据最多加 20 分，提升后不超过 75（本来更高的不降低）。内容不同的旧版本、旧个人文件、未经内容校验的压缩包等，只凭名称不能再加分（`insights.content_question`）。体检的 AI 复核从不发送内容；体检方案和「我的文件」页用同一条规则。

**评分不能自己给自己作证。** 一项的分数只能来自互相独立的依据：AI 收到盘序的线索（「较旧的版本」「旁边有同名文件夹」「旁边有更新的版本」）时，如果它能看到的也只有这条线索，它的「可以删除」就只是复述，不能再加分。目录不受影响：AI 看到的是文件类型分布、最大的文件和子目录，是线索之外的依据。2026-11-04 按这个原则排查了全部评分来源，另外改了：

- AI 判「需要你确认」的目录以 5 分为基础（`AI_REVIEW_SCORE`），遇到近期活动、程序归属或未完整扫描等情况再降低，不把 AI 的把握直接换算成分数。
- 没有 AI 时的目录启发式（旧版本、卸载残留）加上底线：里面有 .exe / .dll 的（空间扫描标记 `FLAG_PROGRAM`，向上汇总）不自动勾——可能是程序本身，例如并排装着的两个版本。卸载残留在积极档仍然自动勾（维护者的决定），这条底线挡住最危险的情况：没有登记的绿色版程序。
- 名字只差日期的一组（`账单_202401` / `账单_202402`、`年报_2023` / `年报_2024`）常常是不同时期各自的文件，不是同一份的草稿：较早的标「日期较早的一份」，2 分，说明里写明两种可能。
- 体检方案不放小于 1 MB 的个人文件（`PLAN_MIN_FILE`）：释放不了空间，只增加删错的机会；它们仍在「我的文件」里。
- 重复文件里，程序文件夹和代码工程里的副本标出它在哪里（`duplicates.place_of`：程序 / 工程 / 工程的构建输出），因为两个绿色版程序里同一个 DLL、两个工程各自 `lib\fonts` 里的同一个字体，每处都可能引用自己的那一份。真实电脑上 37 组重复文件里有 20 组是这样的，例如几个版本的视频项目各自 `public` 里的同一段音乐。维护者要求仍然列出来、由用户自己判断，只是分数低：
  - 有零散副本、也有程序或工程里的副本：保留程序和工程里的，只删零散的（85 分，内容不会丢失）。
  - 「工程旁边」：放着代码工程的文件夹里其他地方的副本（`萍萍瑜伽故事\audio\mix.wav` 旁边是 `萍萍瑜伽故事\代码工程`）常常是工程的素材，脚本可能从那里读取；要删的副本里有这种时 5 分，不自动勾。用户选来查找的文件夹本身和盘符不算（Documents 下直接放着一个工程，不等于 Documents 里的东西都在它旁边）。真实电脑上 `E:\Document\ChatGPT` 的 80 组：以前 9 分的 17 组现在都是 5 分（音频素材在工程旁边），其余 3 分或 5 分。
  - 每一份都在程序或工程里：3 分，说明「它们可能各自引用自己的那一份」；只有要删的全在构建输出里时 5 分（重新构建会再生成）。保留时先留程序里的，再留工程源文件里的，最后才是构建输出。
  - 「重复文件」页的自动勾选同样不勾程序和工程里的副本；每一份都在里面的组写明为什么没勾。标签带两级文件夹名（「萍萍瑜伽故事\代码工程」），同名的工程文件夹也分得清。
  - **工程用没用到它**（`duplicates.check_references`）：查找完后，在每个副本所在的工程（工程旁边的副本就在放工程的那个文件夹）里，按文件名搜索代码和设置文件（`REF_EXTS`：js/ts/css/json/py/cs、Unity 的 .meta/.prefab、Godot 的 .tscn 等；跳过 node_modules、.git 和构建输出；每个文件夹最多 2 万个文件、200 MB）。只读、在本机、每个文件夹只读一遍。有文件提到 → 这份必须保留（2 分）；搜完都没提到 → 很可能没在用（工程里 6 分、工程旁边 7 分）；运行时拼出来的文件名搜不到，所以「没提到」只降低风险，说明里会写明。真实电脑上 `E:\Document\ChatGPT` 189 个副本里 157 个被提到（工程的 manifest、QA 清单、样式表），搜索 3 秒。
  - **AI 帮你分**（`Analyst.review_duplicates`，「重复文件」页的「让 AI 看看这 N 组」，体检的 AI 复核里最多 36 组）：只发送副本的路径（用户名隐藏）、修改日期和盘序查到的情况（在哪里、谁提到它），请模型对每一份说「更推荐删除 / 删前确认 / 建议保留」和理由。它补的是盘序看不出的含义：`lib\fonts` 是随工程带的字体，`public` 里的素材页面会直接加载，`engine_film_v6` 是 `v9` 的旧版本。盘序查到的事实优先：程序里的、被提到的副本，模型说「删除」也只算「删前确认」。分数上，「建议保留」压到 2 分、「删前确认」压到 4 分，「更推荐删除」只加 1 分、不超过 7 分；模型还能帮着选保留哪一份。「按 AI 建议勾选」只勾「更推荐删除」的，每组至少留一份。真实模型（DeepSeek）在演练环境里的判断：旧短片工程里没人提到的字体「更推荐删除——已被新工程取代」，样式表引用的那份「建议保留」。

**拖动选择文字不算点击**（`app.js` 的 `PX.endsSelection`）：在一行里拖动鼠标复制文字，松开时浏览器会把它当成对这一行的点击，展开这一行并重画，选中的文字就没了。现在结束一次文字选择的点击（按下后移动过，或双击选词）在捕获阶段被拦下，单纯的点击照常展开。

**一组的勾选框**（`PX.groupBox`）：首页方案的每个分类、垃圾清理的每一组、我的文件的每一类，标题前面是一个三态勾选框——全选是勾、选了一部分是一横、都没选是空；点一下全选，全选时点一下全不选。它和行里的勾选框在同一列，标题和行的文字对齐。「同一文件的多个版本」也有这个框：全部版本都勾上是允许的（维护者决定，和重复文件一样），这一组里和移到回收站的确认框里会用琥珀色写明「一个版本都不保留，只能从回收站还原」；「只选可以删除的」按钮还在。

**展开一行**（`PX.detailPanel`）：每个页面展开后的内容放在固定的位置，看熟一次就知道去哪里找：第一行是会做什么（「移到回收站 · 需要时可以还原」「永久删除 · 不经过回收站」「禁用开机启动 · 随时可以重新启用」）；然后一条琥珀色的提醒（受保护位置、规则的注意事项）；左边是几条短事实，每条一个小标题（是什么 / AI 认为它是 / 建议 / 还要知道 / 有多少），行里已经写过的话不再重复（评分依据里「分类：原因」和行里的原因一样时也省掉）。方案项的字段各有一个意思（`checkup.PlanBuilder`）：`why` 是行里那句为什么列出来，`what` 只放「它是什么」，`advice` 是该怎么处理（我的文件的分类建议、仅供了解的处理办法），`effect` 只放操作本身之外还要知道的后果（「如果还在用旧版本，它的设置和缓存会丢失」）；「移到回收站，需要时可以从回收站还原」这类套话不再写进去。右边是建议清理度卡片——左边框和分数用这一档的颜色（绿 / 琥珀 / 灰），下面是评分依据：绿点是支持清理的证据，琥珀点是让它慢一点的理由（守卫、可能被用到），蓝色菱形是 AI 的话（`PX.basisKind` 按 checkup 写的句子归类，有单元测试），最后一条虚线下面是勾没勾、为什么；最下面是位置，一行一个，重复文件的副本带「保留」「移到回收站」标记，下面一行是它在哪里、谁提到它、AI 怎么说。窄窗口时（面板宽度小于 640px，容器查询）左右两栏变成上下排列。刚展开的那一块淡入（`.dp.enter`，只在打开的那一次）。

**重复文件由你挑**（`api.m_plan_dup_choose`、`checkup.dup_choice`）：首页重复文件一项展开后，每份副本前面有勾选框，勾上的移到回收站，任意挑。改了以后这一项按同样的规则重新算：要删的里风险最高的那份决定分数，评分依据跟着变（删掉被工程提到的那份会写明），执行的就是挑好的那几份。全部勾上也可以（维护者决定：用户愿意就由他，提示清楚即可）：这时删的就是文件本身而不是多余的副本，这一项 2 分（`ALL_COPIES_SCORE`），行里写「这 N 份全部移到回收站」，展开后和清理确认框里都有琥珀色提示「一份都不保留，只能从回收站还原」；「重复文件」页同样允许，组里和确认框里提示。自动勾选和「按 AI 建议勾选」仍然每组留一份——整组删除只能是用户自己勾的。

**进度**（`checkup.run` 和首页的 `checkupProgress`）：体检是一条进度条，每个阶段占一段。每段占多长，用这台电脑上一次体检各阶段实际用的时间（`checkup_timings.json`，`load_timings`），第一次用一个常见比例。阶段内部，后端能算的就报 `part`：垃圾规则按条数、空间扫描按已统计的字节占扫描磁盘合计已用空间、重复文件按「快速比对 / 逐字节比对 / 查看工程」三段各自的进度、AI 复核按它的几个小步骤和已问的次数；「整理我的文件」没有总数，只报已看过多少个文件，进度条按上次这一段用的时间慢慢往前走（走到九成为止），所以不会停着不动，也永远不倒退。下面一行左边是正在做的事的计数（「已统计 412,000 个文件」），右边是已用时间和「预计还要约 N 分钟」：有上次的时间就按它算，没有就等进度过了 15% 再按目前的速度估，并且平滑处理，不会一会儿 1 分钟一会儿 5 分钟。清理时的进度条是已释放 ÷ 选中的大小。

**清理之后**（首页 `reportBox`、`handled`）：可用空间旁边是这次真正多出来的空间（「+7.8 GB」，清理前后系统盘可用空间之差：回收站里的不算，因为它们还占着空间）。最上面一张结果卡片，三个数字各说一件事：「已释放」（永久删除的缓存）、「在回收站」（需要时可以还原，清空回收站后才真正释放）、「个开机启动项已禁用」；有没完成的，卡片边改成琥珀色，下面逐项写出原因。总览和各组只算还没处理的（「还有 N 项可以处理」）；处理过的项目——这次清理的、在工具页里处理掉的——收进最下面一张折叠的「已处理」卡片，每项一行：「已清理，释放 2.3 GB」「已移到回收站（6.2 GB），需要时可以还原」「没有完成：原因」。大小由后端作为数字给出（`item['freed']`），界面统一换成 KB / MB / GB，不再出现「释放 N 字节」。

**删除进行中**（`PX.deleteFlow`）：进度对话框不会因为点了窗口别处或按 Esc 而消失（`PX.modal({ locked: true })`）——以前一点就没了，删除还在后台跑，界面上什么都看不到。它显示正在移的那一项、第几项 / 共几项、已用时间，并说明大文件夹可能要几分钟、Windows 会显示自己的进度窗口、放不下的 Windows 会问要不要直接删除。完成后的对话框分开写「移到回收站 N 项」和「直接删除 M 项」，有直接删除的标题就是「完成，部分已直接删除」，并用琥珀色写明不能从回收站还原（`PX.deleteResult`，我的文件的移到回收站也用它）。

**动画不被重画打断**：任务进行时页面每 300 毫秒重画一次，进度条每次都是新元素。`PX.progressBar(fraction, key)` 记住同一个 key 上次停在哪里，新元素从那里开始、用和轮询间隔差不多长的线性过渡滑到新位置，连起来就是连续地走；不知道多少时的来回扫动、当前步骤的脉冲，用和时钟对齐的 `animation-delay` 接着上一帧的相位，不会每 300 毫秒从头开始（以前看起来像卡住）。提示条滑入、淡出；系统设置了减少动态效果时全部关掉。

NTFS 默认不在大于 128 GB 的卷上更新访问时间，所以「很久没用」以修改 / 创建时间为主，访问时间只在明显晚于修改时间时参考。

「让 AI 看看这些文件」发送文件名、匿名化的文件夹、大小、日期和分组；文档开头的内容（约 800 字）只有在设置里允许**并且**这一次确认框里再次勾选时才发送，确认框列出会读取的文档，操作记录里记下读了哪些。

### 已安装的应用（`apps.py`）

读三个 Uninstall 键，隐藏系统组件和更新包；有管理员权限时从 `Windows\Prefetch` 得到最近运行时间。Prefetch 只记 exe 的名字，所以「最近运行」只看程序自己的主程序：名字像程序的 exe（Adobe Premiere Pro.exe、AfterFX.exe），没有时取名字最贴近的（ACDSeeUltimate2019 而不是 ACDSeeIndexer），再没有才取文件夹顶层的 exe；更新程序、托盘和同步助手、服务、崩溃报告、卸载程序和 node.exe 这类很多程序都带的运行时不算——它们自己会启动，说明不了你用没用过。程序自己的文件夹也要找对：真实电脑上 Creative Cloud 给八个程序都登记了 `C:\Program Files\Adobe`，以前每个都算上了全部 Adobe 的 exe（包括每天开机自启的 Acrobat 同步助手），全都显示「今天」；现在共用的登记位置下找名字对应的子文件夹。97 个程序里有 46 个没有登记安装位置，以前永远「没有记录」；现在用图标或卸载程序所在的文件夹（版本号子文件夹取上一层，系统目录、安装包缓存和 Common Files 不算）。卸载只运行程序自己的卸载程序（MSI 的 `/I` 改成 `/X`，Steam 游戏走 `steam://uninstall`），盘序不直接删除程序文件夹。卸载程序的进程常常一启动就退出（把自己复制到临时目录再运行），所以「卸载完了没有」看的是它在 Uninstall 键里的条目还在不在——和「设置 > 应用」一样：打开卸载程序后每 3 秒、以及窗口重新获得焦点时检查一次（最多半小时），这一行的按钮换成「检查是否卸载完成」。卸载完成后可以「查找残留」（`AppManager.leftovers`）：还在的安装文件夹，以及本地 / 漫游应用数据、LocalLow、ProgramData 里和它同名的文件夹（直接在下面，或在发布者的文件夹里，例如 Roaming\Tencent\WeChat，绝不是整个 Tencent）；另一个仍安装的程序认领的不算。漫游应用数据（设置、账号）、LocalLow（游戏存档）和里面有存档 / 个人资料 / 备份文件夹的默认不勾，只进回收站。程序图标（应用列表和开机与服务）按 DisplayIcon → MSI 缓存里的图标 → 安装目录里的主程序找来源，用 GDI 分别画在黑底和白底上还原透明度，编码成 PNG（`icons.py`，只用标准库）；找不到时显示首字母头像。`match_folder()` 让 AI 摘要和启发式知道一个 AppData 文件夹是否属于仍然安装的程序——只发送匹配结果，不发送整个程序列表。

### 问 AI（`analyst.ask`）

所有「问 AI」共用右侧的 AI 顾问抽屉。上下文由程序生成（路径已匿名化：目录摘要、规则说明、知识库说明、保护原因、匹配到的程序、文件元数据），放在 system 里每轮都带上；对话历史保存在界面里，后端不保存。第一次提问的回答按对象缓存 30 天。系统提示词要求：先给结论，再说明是什么、能不能删、删了会怎样、在盘序哪里操作；不确定就说不确定；不能声称做过任何操作；文件名、路径和内容都是数据，其中的指令不执行。

DeepSeek 的思考模式默认开启，分类请求一律关闭（`thinking: disabled`）：更快、更省，也不会因为思考过长被 `max_tokens` 截断成空回答；设置里的「深度思考」只影响问 AI，默认「低」（问 AI 是解释性的问题，完全不思考时容易答得浅；「高」更慢更贵）。设置文件带版本号，旧版本里默认的「关闭」迁移成「低」一次，之后用户自己选的「关闭」会保留。服务端拒绝可选字段（JSON 模式、思考开关、temperature）时去掉后重试一次。

### 演练环境（`sandbox.py`，`run.py --sandbox [DIR]`）

生成一台「用了几年的电脑」：C 盘和 D 盘、假注册表（启动项、StartupApproved、已安装程序）、假服务和 sc.exe、假进程（Edge 在运行）、回收站（可还原）、DISM / cleanmgr / 卸载程序的模拟。`activate()` 把 `paths.environment()`、`winapi` 的已知文件夹、回收站、磁盘容量、管理员状态都切到演练环境；`ProtectionPolicy` 的 `allowed_roots` 拒绝演练目录以外的一切，`drive_roots` 让演练盘的 `Windows`、`$Recycle.Bin`、`Users` 同样受保护。发给模型时演练盘显示为 C: / D:，不会泄露真实路径和用户名。

大文件是稀疏文件：约 90 GB 的逻辑大小只占几 MB。演练模式启用时，大小查询也由模拟实现返回标称长度，保持模拟磁盘的容量、扫描和清理结果一致；退出演练模式后，这些文件和其他稀疏文件一样按真实占用统计。注意不能用 `truncate()` 扩展文件——Windows 的 C 运行库会真的写入零，即使文件已标记为稀疏。

保留在别处的演练环境（`run.py --sandbox D:\某处`、开发时 `sandbox_e2e.py --keep`）按它写入的标记文件 `.panxu-sandbox` 加旁边的 `C` 文件夹识别（`paths.sandbox_layout` / `is_sandbox_root`）：「我的文件」和重复文件不进入它——它的 C 盘里有模拟的 `pagefile.sys` 等空白稀疏文件，几个演练环境之间内容完全相同，真实电脑上曾被列成「pagefile.sys 等 3 份」；空间分析标成「盘序演练环境」，AI 分析跳过它。默认位置 `%LOCALAPPDATA%\PanXu\sandbox` 本来就在应用数据里，不受影响。

新代码访问系统位置时一律通过 `paths.environment()` / `winapi.known_folder()`，访问注册表、服务、进程、命令时都要能注入假实现并在 `sandbox.py` 里提供模拟，否则会漏出演练环境。演练用的数据目录是 `<演练目录>\data`，第一次创建时从真实数据目录复制模型设置和 Key。

开发工具：`tools/sandbox_e2e.py` 通过 `Bridge.call` 跑完整流程并逐项检查（`--live` 用真实模型）；`tools/ui_harness.py` 在浏览器里把真实界面接到演练环境的真实后端（只绑定 127.0.0.1，带随机令牌，只用于开发，程序本身仍然没有 HTTP 服务）。

## 尚未实现 / 后续可以考虑

- 应用商店应用的启动任务、带登录触发器的计划任务只能在系统设置里管理，1.0 不列出。
- 休眠文件（powercfg /h off）、虚拟内存大小、系统还原点占用只给出说明，不提供一键操作。
- Docker / WSL 虚拟磁盘的压缩只给出说明。
- 直接读取 NTFS 主文件表（类似 WizTree）可以把扫描提速一个数量级，但需要管理员权限，而且无法在当前的开发环境中测试，暂未实现。
- 以另一个管理员账户提权时，用户文件夹的重定向位置按管理员账户解析。

### 软件残留与失效登记

`AppManager.removed_apps()` 从卸载操作记录恢复程序身份，并重新检查安装登记是否已消失。新写入的日志包含 ID、发布者、注册键与安装位置；旧日志不凭名称伪造确切的卸载身份。`leftovers()` 拒绝仍有登记或被其他已安装程序认领的目录。体检沿用空间树，只读取本次范围中的残留；工具页的 `app_residues_scan` 独立扫描当前账户 AppData、LocalLow、ProgramData 和已记录的卸载位置，不受首页范围开关控制，也不覆盖空间页的树。所有路径仍过 ProtectionPolicy，删除仍经 fsops 并默认回收。

疑似残留门槛从 500 MiB/一年调整到 10 MiB/半年，以创建或修改时间较新者判断活动；旧版本候选从 200 MiB 降到 20 MiB。先筛应用数据再按大小取最多 500 个候选，卸载历史最多处理 100 个程序，达到上限明确提示。没有安装登记不是卸载证据：这一类永不自动勾选，基础 4 分；包含用户资料或守卫命中进一步降分。旧版本的缓存子目录可按统一门槛勾选，整个旧版本设置与历史仍须用户确认。残留建议避开所有规则目标，防止重复计数和绕过保留期限。

结果保存在 `Backend.app_residues`，与首页对应条目共用状态与 PX.sel；软件登记单独列出、不提供删除操作、不计算字节收益。`registry_issues()` 只检查桌面程序的 Uninstall 登记：显式绝对安装路径和 exe 卸载路径都须在当前连接的固定盘上且得到 FileNotFoundError，权限不足、离线盘、相对命令、协议、MSI、运行库及驱动均不据此判为失效。问 AI 会收到这些本地依据。新增系统读取沿用注入的 registry/env/drive_roots，演练模式含失效登记样例。
