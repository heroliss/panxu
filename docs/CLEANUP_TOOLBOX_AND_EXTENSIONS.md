## 目标与现状

用户希望常见操作可以不经LLM直接使用，LLM也能发现和调用同样的能力；未被内置工具覆盖的情况，仍可提出说明、选项与可审阅的执行方案。工具集合是帮助模型工作的基础设施，不是把模型限制为固定清理规则。

| 当前基础 | 实际边界 |
| --- | --- |
| 文件/目录元数据、扫描、哈希查重及建议继承 | 不是完整实时文件管理器，也没有通用正文阅读器 |
| 启动项、服务、进程、桌面软件卸载登记及有限使用线索 | 进程内存主要是快照；不是完整泄漏/长期使用诊断；卸载登记不证明卸载器已经可安全启动 |
| 内存提交量、活动/配置分页、休眠能力、卷容量、回收站统计 | 已有固定只读采集器，没有对应系统配置写入器 |
| 22个模型工具、18类指导、问答、检查点、冻结方案及逐项收据 | 指导不是可执行适配器，唯一PowerShell调用是固定服务查询；没有模型可编写的通用shell |
| 删除、关闭启动项、停止服务、结束进程、卸载的共用生命周期 | 当前全部修改模拟记录；停止服务不等于修改其启动方式 |

## 产品分工

沿用[导航与所有文件方案](NAVIGATION_FILE_WORKSPACE.md)，增加一个“清理工具”入口。普通用户先看到少量常用工具、搜索和“空间/隐私/系统”分类；低频和影响较大的工具按需展示，避免把几十个按钮铺满首页。

- **所有文件**处理文件与目录；**后台与软件**处理进程、服务、启动及软件身份。
- **清理工具**处理系统配置、产品专用缓存/隐私和其他结构化动作；一个工具可以组合多项能力，不复制文件选择及操作记录。
- **当前任务**承载模型会话、问题、进度和额外建议，必要时定位到以上工作区；“额外建议”先作为任务结果分区，不新增一套平行任务系统。
- **常用任务**是目标快捷入口，复用相同能力；“一键清理”是可查看和修改的工具组合，不代表默认关闭休眠、系统还原或清理个人下载。

## 首批工具范围

| 工具组 | 应覆盖的内容 | 接入原则 |
| --- | --- | --- |
| Windows空间 | 临时文件、回收站、系统清理建议、Windows.old、组件存储、传递优化 | 优先系统机制；升级回退文件与普通缓存分别选择 |
| 应用缓存 | 浏览器文件缓存、Store、GPU着色器、游戏/创作软件缓存 | 产品、版本和资料目录单独识别；运行中占用时跳过或等待正常退出 |
| 开发缓存 | uv/pip/npm、Unity等可重建目录、容器镜像及构建缓存 | 官方CLI优先；缓存、依赖、源码、容器卷与环境数据不混为一类 |
| 浏览器隐私 | 历史、Cookie/站点数据、下载记录、自动填充等 | 浏览器、资料配置、时间段和同步范围明确；密码/通行密钥独立，不默认纳入 |
| Windows隐私 | 剪贴板、搜索/活动历史、最近使用/快速访问/跳转列表、诊断数据、位置和应用权限 | 本机记录、显示开关、未来收集及账号云端记录分别处理 |
| 故障与诊断材料 | 崩溃转储、WER报告、应用诊断日志 | 先核对是否仍需排障，按具体来源清理；不把所有日志作为垃圾或默认清空事件日志 |
| 内存与后台 | 提交压力、工作集、常驻与启动、分页/转储配置 | 分析瓶颈和实际用途，不把工作集下降包装成解决泄漏或永久释放内存 |
| 休眠与恢复 | 休眠full/reduced/off、快速启动、低电量动作、系统保护额度及还原点 | 联动展示能力变化；关闭功能与删除既有恢复材料分开 |
| 迁移与云 | 文档/图片/桌面、普通目录、缓存默认位置、云文件本地副本 | 识别重定向/同步/权限及目标卷；改路径、搬内容、校验和恢复是不同阶段 |
| 软件与系统组件 | 正规卸载、应用修复/重置、旧驱动包、可选功能/语言包 | 核验实际卸载入口和依赖；打开卸载器、等待完成和复查残留分开 |
| 高级空间管理 | WSL/VHDX回收、CompactOS/文件压缩、文件历史版本及旧备份 | 不承诺逻辑删除立即缩小宿主文件；官方保留策略与普通备份目录分别处理 |
| 定点故障修复 | 孤立卸载登记、某应用明确的损坏配置等 | 不提供通用“无效注册表一键清理”；仅证据明确的定点修复 |

“全面”表示不断扩充有依据的适配器，不是保证所有系统和软件都有一键清理方法。清理空间、清理隐私、修复故障和改善性能分别标记目的，不混算收益。

## 两种入口，共用一个工具

每项能力分别声明：读取、检查适用性、预览、执行、打开设置、核验、恢复。UI直接点击和LLM调用都进入同一个实现与结果记录，不开发两套清理逻辑。

工具目录保存稳定ID/版本、用途、参数和结果合同、适用OS/软件版本、账户/资料目录、权限、预算、锁定条件、重启要求、影响和恢复能力。模型工具定义、宿主校验、分发和开发面板从同一来源生成，避免文档写一套、实现另有限制。

“直接处理”只在适配器具备能力时显示；另一入口按真实能力命名“打开设置”“打开清理界面”“查看位置”或“查看官方方法”。没有官方设置页或可靠自动化方法时，不凑出一个虚假的对应入口。Windows设置URI按版本/版本类型探测并提供人工导航回退。[微软设置URI说明](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings)

打开设置成功只记录`opened`，不是`applied`。用户返回后重新读取配置；无法核对则记录未核实。某些工具可能只能提供其中一种入口，工具详情应说明原因。

能力发现继续按需：首包给任务目标和紧凑能力索引，模型通过既有discover工具进一步取得少量相关工具合同；不一次发送几十份说明和全部系统信息。参数、输出上限、未知与覆盖范围仍保真。

## 额外建议与按钮选项

扩展既有问答和方案工具，让模型提交一个或多个建议项，内容包括：简短标题、用途/原因、预期收益与影响、适用对象、证据/缺口，以及少量可选方案。保留模型、时间、来源与重新分析后的版本。

每个按钮只能引用一种宿主识别的行为：

1. 回答问题或记录偏好，不立即执行；
2. 打开已注册的设置/程序/位置入口；
3. 为内置工具及参数建立待确认方案；
4. 查看人工步骤或官方资料；
5. 为确实需要的外部程序/控制台动作准备受审阅的扩展方案。

UI由程序组件渲染，不执行模型生成的HTML、JavaScript或onclick。修改型按钮的实际动作名称、数量和影响由宿主补足，不能让“查看详情”之类文字暗中执行删除。未知行为只展示建议，不伪造可点击的执行能力。

建议可以组成清单，勾选后集中预览和执行；保留单项解释、跳过、改选和失败结果。多个互斥选项作为一个选择组，不能同时执行；依赖、冲突及操作先后由宿主整理。文件目录项继续沿用最近路径规则，系统设置项按配置身份，应用/服务按独立身份，不能统一按路径合并。

继续区分清理推荐分和影响程度。较高推荐分不能被当作关闭恢复能力或永久删除的授权；自动初选规则按动作类别和用户已有意图判定，而不是机械复制文件评分勾选到所有设置。

## 从已有建议进入专项清理，再回到原现场

文件/目录以及后台、软件等任何分析结果，都可以在现有建议、原因或影响文字中自然补充“建议通过某专项工具处理”。不增加固定说明区，不重排已有卡片、评分及筛选；只在确实存在相关方案时，于既有行内操作区附加一个次要入口。没有关联时不显示空按钮，多种方案共用一个选择入口，避免一项出现一排按钮。

| 建议内容示例 | 可选入口 | 实际去向 |
| --- | --- | --- |
| 建议使用系统组件清理，保留组件目录 | 打开系统清理 | 已注册工具，带入已核对的相关目标 |
| 建议先正规卸载，再检查程序残留 | 查看卸载方案 | 软件/卸载工作流，完成后复查原目录 |
| 建议用浏览器自身功能清理文件缓存 | 打开浏览器清理 | 对应产品及资料配置的工具或可靠设置入口 |
| 当前情况需要按应用要求分步处理 | 查看专项方案 | 同一任务内的额外建议对话及其选项 |

以上仅为产品行为示例，不表示当前适配器已存在。“打开”“查看”“执行”按实际行为命名；只是跳转时不能写“执行专项清理”。工具已具备执行能力时，仍进入其现有预览和确认，不再叠加一套专项确认体系。

建议正文和可执行关联分开保存。正文供阅读；关联以可选结构引用内置工具或额外建议，携带来源任务/建议版本、对象身份和签名、账户/Profile、已知参数及待回答项。宿主验证引用及参数，不能从模型写的工具名称、文件路径或自然语言中猜一条命令。现有建议没有该字段时仍按原方式显示，不增加首包全量采集；模型按需发现工具后才补充关联。

评分、建议说明、具体动作和导航入口是不同维度。仅补充“也可使用某工具”的文字，不修改已有评分、勾选或动作；若模型明确判断应由专项工具替代整目录删除，则该建议不能因4–5分又自动生成删除目录方案。当前files-only手选及任务默认动作有delete映射，实施时必须核对该兼容路径：保留原普通文件操作能力，但不得把专项动作悄悄转换成delete。用户明确另选普通删除时，仍走原来的对象检查和冻结流程。

目录子项可以继承可读建议和指向上级专项方案的入口，不继承或放大工具执行范围。多个对象关联同一个工具/账户/Profile/参数及方案版本时共用一次操作；原建议清单和完整目录视图引用同一关联，不按子项或入口重复执行。跨任务的批准仍分别有效，不能因工具相同合并授权。

路由保存可续接的来源任务、工作区、视图、目录、筛选、分页/滚动锚点、焦点及版本化选择草案；专项工具、软件流程或额外建议完成/取消后，提供“返回清单”或“返回上一步”。不为每次跳转新建独立任务，不重置原选择。工具界面预填已知信息，缺失再问；若实际操作覆盖的Profile/系统范围大于来源目录，必须明确展示差异，不能以来源路径掩盖更广作用域。

专项方案生成与执行结果关联原建议及同一任务。只刷新确实受影响的文件/配置及状态，保存原模型、时间、说明和操作来源，不用工具结果冒充模型重新分析。取消、未执行、部分成功、失败及待重启分别显示；打开设置只表示已打开。清理缓存不表示目录已删除，空间回收以实际核验为准。发生变化的旧对象/计划需失效重核，不能继续按旧高分或旧签名自动重复处理；不为每次返回强制重扫整个磁盘或再请求一次模型。

实施验收包括：旧建议无关联时不变；同一关联在任务/完整视图一致；仅打开不执行；工具不可用时保留文字并提供准确替代方法；往返保留选择和位置；专项替代删除不误编译；继承/多入口不重复执行；目标失效、部分结果、待重启及应用重启后续接均保持真实。

## 控制台作为扩展适配器

先实现有参数合同的系统/产品工具和固定只读查询；通用控制台作为后续能力，不能声称当前已经支持。确需控制台时，模型先提出完整方案：解释器、完整命令/脚本、参数、工作目录、对象范围、权限、预期变化、核验方法及恢复条件。

审阅后冻结以上内容和哈希；随后改写脚本、目标、权限或下载依赖需要重新核对。用户可以看中文摘要，原始命令在详情及开发面板中可读可复制。正常应用不永久以管理员身份运行；系统级操作交给单次、限任务的提权适配器，UAC取消与权限不足分别记录。

工作目录、危险词检查、命令标注“只读”、超时或PowerShell执行策略均不是对任意脚本的可靠隔离。若提供通用脚本能力，必须如实说明其有效权限；需要真正隔离时评估独立受限进程、系统策略或虚拟环境，不能仅以runspace语言模式冒充安全边界。[微软PowerShell安全说明](https://learn.microsoft.com/en-us/powershell/scripting/security/security-features)

不把管道下载后执行、自动安装陌生清理器、递归扩大删除范围或绕过Windows保护包装成一般扩展按钮。第三方程序先识别本地路径、版本和发布来源；缺依赖则转为安装/人工步骤建议，而不是静默安装。目标程序或命令输出也不是新的用户授权。

## 一条执行与反馈链

复用现有ActionRuntime、检查点、用户问答、冻结方案及收据，而不是另写“工具执行历史”：

发现能力/读取事实 → 生成建议或用户直接选择 → 预览并冻结 → 明确确认 → 逐项执行 → 复核 → 记录结果 → 将用户决定与真实结果带回任务。

点击已知内置操作不必额外请求LLM来重复发命令。先持久保存选择，再由宿主执行；模型继续调查时可以取得已保存结果，是否再请求模型由需要的后续推理决定，不为每次按钮点击增加一次调用。

操作记录保存原值、期望值、实际值、退出码、逐项结果、可恢复性及需重启状态。中断后先核实，不自动重放非幂等动作。模拟和真实后端共用计划和记录格式，但分别核验虚拟收据和真实后置条件，不能用模拟成功冒充Windows已改变。

需要重启才生效、待重启删除、卸载器仍在运行及空间尚未释放分别保留状态；退出码成功不直接等于全部完成。重启或返回应用后继续核对同一操作，不因暂未释放空间就重复删除或卸载。

暂停/取消在工具允许的安全阶段生效，不承诺所有系统命令能随时中断。批次出现互斥设置、卸载/运行占用或共享缓存依赖时先整理顺序，不能盲目并行。

## 隐私、收益与恢复的真实含义

- 浏览器文件缓存、登录Cookie、站点离线数据、历史、密码、下载历史和实际下载文件分别建模；本机与同步/云端的删除范围必须明确。
- 隐私清理的收据只保留类别、时间范围、数量和结果等必要信息，不把已清URL、Cookie、密码或剪贴板正文再存进操作日志或发给模型。
- 对隐私数据默认再做完整内容备份会违背清除目的。只有确实可恢复的内容才展示恢复入口；“配置可改回”不等于“被删除数据可恢复”。
- 临时备份有保留期和清除入口；同盘转到备份或回收站通常不释放该卷空间，跨卷迁移只是改变占用位置。逻辑大小、可清估计与实际卷可用空间变化分开，未知不写0。
- 不把通用注册表清理、强制清空工作集、删除系统安装缓存、关闭安全保护或删除所有还原点放进常用默认组合。

## 分步开发

1. 注册中心、配置/隐私目标类型、统一设置跳转和额外建议卡片；先只读与模拟，保证来源、状态、用户决定及结果可恢复。
2. 常用文件操作、正规卸载入口、Windows系统清理入口、浏览器自身清理界面；逐工具完成直接操作适配及本机核验，不整包宣称可执行。
