# 设计决策记录

初始记录日期：2026-11-01，后续追加见各条日期。状态为已采取的设计方向；未来条件满足时可以重访，但需记录新的证据与取舍。这里的产品决策不表示相关真实执行能力已经交付。

记录按时间保留，后续条目明确更新的部分以新决策为准。通信与分层输出见D038，自动初选、最终个人选择和目录例外见D039；早期“不默认勾选”和“仅本页”的描述不替代可修改草案与明确确认的合同。独立重复查找和页面分工见D040–D041，响应预算、调查收束与公开动态见D042–D043，摘要显示与有效性的界限见D044。跨对象清单与统一模式提示见D045–D046，后者更新D034中按钮重复加“模拟”的旧呈现约定。v0.15的五级颜色、五段加文字与卡片层级见D047，更新D037的可见数字取舍；v0.16的全入口按需输入见D048，独立影响与柔和配色见D049，有限UserAssist证据见D050。D048更新历史首包样本策略，D049更新D047的固定warning影响底色，不改评分和选择语义。v0.17按D051增强表面、字阶和舒适色彩，D052开放文本选择并防止拖选误触；源码与最终原生验收分别记录，历史验收不代替新产物验收。

## D001：使用同一仓库作为长期代码基地

- **采取**：在本目录持续开发，保留设计、测试、实现与发布记录，通过 Git 和 GitHub 积累可审阅提交。
- **放弃**：每次对话另起一次性演示目录，或把工程与私人扫描输出混放后整体清理。
- **原因**：产品需要连续修复、回归验证和可追溯取舍，不能只保留某次可运行的产物。
- **重访条件**：确有模块独立发布、仓库规模或维护权限问题时，再明确迁移与历史保留方案。

## D002：正式面向普通用户，以渐进披露组织信息

- **采取**：先给用途、结论与影响，再展开技术依据；新手主流程与进阶明细共用同一真实库存。
- **放弃**：把原始路径表格、工具追踪与技术开关当作默认首页，要求用户自行扮演系统专家。
- **原因**：帮助理解和决策是产品职责，技术透明不等于默认展示全部实现细节。
- **重访条件**：真实可用性测试显示关键风险被隐藏时，增加必要提示；专业功能可扩展进阶视图，不反向压倒默认体验。

## D003：每个阶段只有一个主要 CTA

- **采取**：围绕“开始检查 → 查看建议 → 确认处理 → 记录”组织操作，目录、去重与设置作为次级入口。
- **放弃**：多个并列的大按钮和分散的确认入口，让用户不清楚下一步。
- **原因**：降低选择成本，保持一批操作范围与结果可理解。
- **重访条件**：出现明确不同的高频用户目标时，可增加任务入口，但需重新验证默认路径与作用范围。

## D004：由规则与证据守边界，由模型承担非个人判断

- **采取**：程序控制保护、范围、动作、预算和验证；LLM 提供结构化的非个人建议与白话解释。
- **放弃**：让 LLM 自由执行终端，或把所有项目都退回“你自己判断”，使模型只剩聊天包装。
- **原因**：既要减少用户负担，也要让模型建议受实际能力和可核查证据约束。
- **重访条件**：新动作具备明确契约、权限、核验和恢复测试后，可以作为受控能力加入；不能靠更长提示词替代执行层约束。

## D005：个人内容的最后选择权始终属于用户

- **采取**：下载、创建和用途未知文件保持个人组，不默认勾选；模型可解释、比较和建议动作。
- **放弃**：用模型分数、文件日期、扩展名或自定义要求自动替用户删除个人资料。
- **原因**：程序无法从元数据判断纪念价值、离线留存和未来用途；内容相同也可能分别承担路径引用。
- **重访条件**：用户建立明确、可撤销、限定用途的规则时，可设计单独授权流程；不能把一次“按建议处理”扩成永久授权。

## D006：缓存依据来自受管根验证，不能来自名称

- **采取**：当前采集器验证受管位置与 `decision_context`，默认选择还要求可再生成性和完整性证据。
- **放弃**：看到 Temp、cache、AppData 或旧日期就认定是垃圾；为兼容旧数据放宽默认选择。
- **原因**：普通下载目录可以拼出相同的路径片段，项目工作数据也会命名为 cache。
- **重访条件**：增加经过验证的缓存配方和应用适配器。旧目录快照需重检，不通过兼容层追认可信。

## D007：完整缓存目录根优先，避免默认选择所有叶子

- **采取**：经完整检查的推荐目录根作为默认操作单位；被覆盖子项保持推荐但取消重复自动选择。
- **放弃**：把几千个文件分别勾选、分别计量，再让用户处理计划条数超限或重复空间估算。
- **原因**：目录根更符合普通用户心智，也使批次范围更易审核。子项取消默认选择不等于变成个人资料。
- **重访条件**：子树包含个人、受保护、未知或未完整核查内容时，应拆分或保守阻断，不能为了方便坚持整目录处理。

## D008：以独立模拟覆盖层开发，不宣称真实释放

- **采取**：先验证真实只读库存、建议、计划和 UI；处理、撤销与记录仅修改 SQLite 覆盖层。
- **放弃**：早期直接接永久删除，或把界面上的模拟体积包装成实际释放量。
- **原因**：策略与交互需要反复验收；真实执行必须有单独的授权、恢复、失败和结果证据。
- **重访条件**：受限真实执行器、隔离与恢复协议、失败注入和 Windows 端到端验证全部完成后，建立独立发布阶段。不会用隐藏配置把当前版本切成真实模式。

## D009：模型输入最小化，决策输出结构化且有预算

- **采取**：结构化推荐最多 100 个代表候选，对话只给 3 个范围受限的只读工具；默认隐藏路径并严格验证 ID 与动作。
- **放弃**：整盘数据或文件正文上传、无限循环、把自由文本当作最终选择结果。
- **原因**：控制隐私、成本、延迟与越界行为，并能解释模型究竟覆盖了哪些项目。
- **重访条件**：有实际覆盖不足证据和明确预算时再设计分批任务；需要额外元数据必须说明用途和副作用，不静默增加外发范围。

## D010：密钥与服务来源绑定

- **采取**：Windows 用 DPAPI 保存用户密文；公共设置不回显；改变来源时明确替换或清除旧密钥，禁止静默复用。
- **放弃**：把密钥明文存入工程、日志或发布包，或者切换到另一服务商后沿用旧认证头。
- **原因**：配置修改不应成为凭据误发通道，本地应用也不应把调试异常当作凭据日志。
- **重访条件**：支持多提供方档案时，需为每个来源单独建密钥与权限模型，并保持迁移和清除语义明确。

## D011：重复内容是证据，不是自动删除许可

- **采取**：明确选择后执行有预算的本地 SHA-256 校验，区分硬链接、内容重复和路径用途。
- **放弃**：仅按文件名或大小宣称重复，或校验相同后自动删除副本。
- **原因**：模型、项目和备份可能依赖不同路径；逻辑重复也不保证能释放相同物理空间。
- **重访条件**：建立具体应用引用识别与恢复策略后，可提供更精细建议，仍需区分个人选择与受管副本。

## D012：Windows 能力逐项声明，不把枚举包装成控制

- **采取**：明确 Run、启动文件夹、CIM 服务、进程快照、传统桌面卸载注册项的覆盖范围；控制动作目前仅模拟。
- **放弃**：声称“全系统自启动优化”“所有软件卸载”“完整服务依赖分析”，或仅凭工作集高就结束进程。
- **原因**：不同入口、权限与依赖关系差异很大，局部清单不能证明系统全貌。
- **重访条件**：各适配器取得覆盖、权限和真实结果的独立证据后，再扩展能力声明。

## D013：数据留在本机，源码发布与用户数据分离

- **采取**：代码、设计、夹具和可复现构建材料进入仓库；数据库、私人路径、账号配置和原始验收材料默认留在本地。
- **放弃**：为方便复现把整份运行目录、个人截图或提供方配置上传 GitHub，或把已忽略文件视为历史中从未出现。
- **原因**：持久化状态本身包含隐私；发布与提交需要分别检查当前文件和版本历史。
- **重访条件**：确需共享诊断时，设计用户主动导出、字段脱敏与可预览流程，不能直接上传原始数据。

## D014：按最终产物验收

- **采取**：源码测试、真实 Windows 窗口、打包资源和最终构建散列分别记录；结果对应明确提交。
- **放弃**：仅凭源代码测试通过、页面能打开或打包命令成功就宣布产品完成。
- **原因**：桌面依赖、资源路径、运行状态和打包产物可能与测试环境不同。
- **重访条件**：验收可以自动化，但仍需覆盖最终用户实际拿到的产物，并保留未验证项。

## D015：工程迁入正式项目目录（2026-11-01）

- **采取**：按用户要求，将本机工程整体迁至 `E:\GPT-Projects\win11-disk-assistant`，保留 `.git`、源码、文档、构建产物及本机记录；GitHub 代码基地不变。
- **放弃**：继续放在“杂项”目录，或只搬源码后遗失开发记录与运行数据。
- **原因**：项目已进入持续开发阶段，需要稳定、明确的工程归属。启动与构建入口按自身位置解析，迁移不依赖旧目录。
- **核验**：迁移前后 1,116 个文件及总大小一致，Git HEAD 一致；从新位置启动的 v0.2.0 原生窗口和健康接口均正常。此项只证明迁移与启动，不替代完整功能验收。
- **重访条件**：多设备开发、发布与用户数据目录需要进一步分离时，再制定迁移规则；历史报告保留当时路径，不进行全局替换。

## D016：以 LLM 任务循环为下一阶段主线（2026-11-02）

- **采取**：模型根据用户目标主动调查、提出方案、接收选择和操作反馈并继续工作；程序提供事实、经验、工具、持久任务状态与渐进式 UI。详见 `AGENT_ARCHITECTURE.md`。
- **放弃**：继续以固定规则扫描为主、给 LLM 一次性补说明；遇到未覆盖情况就停止调查并让用户自行判断。
- **原因**：用户希望产品能泛化到未知应用、目录和个人整理任务，并通过多轮协作逐步达成目标。规则应降低重复劳动，不应成为唯一的语义决策来源。
- **对旧决策的影响**：演进 D003、D004、D006、D009 的入口、调查路径与工具覆盖；保留个人最终选择、事实核验和用户保留要求。当前 v0.2.0 的既有限制仍如实标注，不伪称已实现新的循环。
- **重访条件**：用实际整理任务验证调查成功率、用户决定次数、解释清晰度、时间与成本；再决定复用何种 runtime 和 SDK，不默认绑定某个模型供应商。

## D017：模拟与真实后端共享动作契约，记录承载实际证据（2026-11-02）

- **采取**：计划、执行生命周期、结果、操作事件与恢复信息尽量共用；模拟修改虚拟状态、真实后端修改真实环境，均进行前置和后置验证。操作日志记录真实观测或明确标识的模拟结果。
- **放弃**：模拟永远记录成功，或两种模式各自实现一套产品流程；把操作日志本身当成已发生副作用的证明。
- **原因**：开发需要复现失败、部分成功、目标变化和中断；相同 UI 与契约可以验证完整反馈循环，但模拟不能证明真实操作成功或真实空间已释放。
- **对旧决策的影响**：演进 D008 的覆盖层和记录架构；当前版本仍 simulation-only，真实执行器另行设计和验收。
- **重访条件**：明确动作数据库迁移、每类操作的核验与恢复能力后进入实现；先使用夹具验证中断恢复与幂等处理，不对用户数据注入真实故障。

## D018：先交付一条有界任务循环（2026-11-02，v0.3）

- **采取**：持久化目标、选择、观察与方案；模型按需调用 9 种工具，用户保留/调整后继续；确认具体版本后逐项模拟处理，结果回到同一模型任务。
- **取舍**：先支持局部元数据、软件盘点和本地重复核对，暂不引入正文上传、网络工具或新模型框架。旧规则检查作为可选入口保留；不依赖无人产生的“无用已验证”标记才能提出方案。
- **原因**：先用完整任务检验协作价值，确保用户选择实际影响下一步，而不是只修改推荐页文案。模型供应商继续通过已有兼容传输接入，需支持工具调用。
- **实现边界**：每轮 6 次模型响应、12 次工具调用，目录最多4,000条/次，方案最多30项。保存本机任务与有界观察摘要，不保存提供方原始响应或内部推理。工具以 ID 引用用户范围，用户明确保留的目录子项也不能被整目录方案覆盖。
- **界面取舍**：延续深蓝侧栏与灰白工作区。首页只呈现目标、位置和一个主按钮；过程、影响、历史和补充要求按需展开；具体动作与未完成结果属于必须及时显示的信息。
- **验证**：离线单元测试、真实回环 HTTP 模型与可丢弃目录的界面流程分别验收；真实提供方兼容与实际任务质量仍待用户配置后验证。

## D019：按用户意图进入调查，移除独立基础检查（2026-11-02，v0.4）

- **采取**：首页四个常用任务；额外任务折叠。预设提供目标、范围和有用的缓存起点；模型继续负责选择调查步骤和解释，工具保留程序化采集与核对。
- **放弃**：让新手先填写开放提示，或把只覆盖四种缓存根与部分后台清单的基础检查当成全机清理入口。旧接口保留兼容，产品没有入口。
- **原因**：普通用户更容易表达“整理下载”“清理 C 盘”等意图。固定检查结果少反映覆盖有限，不证明机器没有其他可整理内容。任务名称不承诺穷尽全盘。
- **限制与重访**：目前没有真实删除、完整应用知识、正文理解或网络研究；真实模型兼容性和任务质量还需要验证。预设不是新的自动清理配方。

## D020：服务端分页与摘要启动，保留独立选择（2026-11-02，v0.4）

- **采取**：缓存只读库存视图，目录去重与祖先覆盖按路径深度计算；首页只取摘要，文件每页 50 项。搜索防抖与取消、响应序号、8 页缓存及有限 DOM。详情和应用清单按需读取。
- **放弃**：整份清单启动时传输、前端反复对全量目录做两两比较、每点击一次追加 300 行。单纯把同步函数包成异步不解决这些成本。
- **决定权**：跨页选择独立保留，签名绑定原选择；新扫描/保护策略使页版本失效，已变化的选择在计划前被拒绝。完整库存的保护校验不能被分页削弱。
- **限制与重访**：服务端搜索仍按当前库存线性筛选。若库存达到十万以上，再考虑 SQLite 索引与持久分页；当前先解决已经观察到的几千项卡顿，不为未来规模引入复杂前端虚拟滚动。

## D021：各类列表采用先分析、再审阅处理的共同流程（2026-11-02，原提案；0.5实施）

- **方向**：单项、勾选和筛选全集均进入同一任务；分析选择与处理选择分开。原始列表以分析为主，处理按钮在建议方案中出现，高级手动处理单独收起。
- **原因**：当前原始清单容易把“可加入处理”与“需要了解用途”混在一起；普通用户应先得到建议，保护对象也可以在允许的元数据范围内解释。
- **目录策略**：默认按需聚合与展开，逐项详细作为可选方式。节省模型 token 不得省掉目录完整性、受保护子项和执行前核查。
- **取舍**：共用对象、建议、动作记录与任务循环，文件、配置、进程和隐私分别保留动作与恢复语义。回收站是恢复途径，不统一标为独立备份。
- **实施依据与验收**：[统一流程提案](UNIFIED_ANALYSIS_FLOW.md)。用户本轮要求先完善方案，当前 0.4.0 程序与模拟边界保持不变。

## D022：服务商预设需要协议适配与工具往返测试（2026-11-02，原提案；0.5实施）

- **方向**：服务商、模型和密钥为简洁入口，预设封装官方地址、协议与可用参数；自定义连接和高级控制保留。
- **原因**：当日官方文档确认最新 OpenAI 工具调用与 GLM、DeepSeek 思考续接存在实际协议差异。只换 URL 和模型名字不足以承诺兼容。

## D024：任务记忆属于程序状态，扫描与模型轮次分别续接（2026-11-02）

- **采取**：将目标、范围、用户选择、版本化方案、事实引用、扫描进度和核验结果保存为可查询的任务状态。每次继续调查，依据这些资料重新建立上下文；模型的私有思考、签名或加密续接只服务于当前连接中的协议往返，不作为跨模型记忆。
- **原因**：聊天记录不能证明目录检查到了哪里，也不能证明操作已经生效。更换服务商或意外中断后，新模型需要有来源和覆盖范围的证据，以及尚未完成的事项。
- **扫描取舍**：用本地持久索引与有界工作批次推进大目录；返回摘要和分页引用，避免重复同一前缀。索引记录观察时间与不完整状态，不代表永不过期的文件系统快照，也不能替代执行前身份核对。
- **界面取舍**：普通层沿用“继续调查”；覆盖、累计工作量和交接说明放在任务详情。不要求用户理解游标或模型协议。
- **限制**：不承诺故障发生时尚未落盘的最后一轮推断可以恢复，也不保证更换模型后判断完全相同。真实删除和恢复仍须独立实现；本版只核对模拟收据。

## D025：程序目录优先走正规卸载，卸载后再观察残留（2026-11-02）

- **用户意图**：针对不用的软件给出卸载建议，可从建议直接进入正确的卸载入口；返回盘序后重新检查是否有可清残留。找不到入口时仍提供清楚的替代步骤。
- **方向**：模型根据目录、安装登记与发布者信息判断用途；本地程序核实应用关联和卸载入口。入口只能来自已核对的系统/应用资料，不能执行模型自由文本猜出的路径或命令。程序目录的分析授权不等于卸载整套软件的批准。
- **入口层次**：经验证的正规卸载器、Windows“已安装的应用”、厂商维护/卸载工具及明确的手动步骤。MSI、Store、便携应用和损坏登记分别说明；打开设置页、启动卸载器、卸载完成是不同状态。
- **结果核对**：用户回到盘序后重新采集安装登记、目录、相关后台和启动信息，不以启动进程或窗口消失判定已卸载。重启待处理、取消和失败分别显示。
- **残留取舍**：缓存、日志和旧安装器可以建议；个人资料、项目、许可证、用户配置以及共享组件分别核对，不能把“仍存在”直接推为“可以删除”。跨模块引用相同应用身份与任务事实。
- **本轮边界**：接入调查提示与后续路线；现有软件清单只保留是否有卸载入口等有限登记信息。尚未实现路径级应用关联、验证后的卸载入口按钮、真实卸载或专门的残留检查。它们应由独立适配器和可丢弃安装夹具验收，不塞进当前模拟执行接口。

## D026：用技能帮助模型判断，用工具执行，用 UI 承载协作（2026-11-02）

- **用户意图**：清理 C 盘时，模型可主动建议迁移文档等系统已知文件夹或普通资料目录；在适当时机提出问题和选项。用户与模型的对话通过文件列表、建议、选择及结果表达，避免为每一种建议写死触发逻辑。
- **技能层**：按需加载带来源、适用条件与版本的任务指南。包括何时考虑迁移、应调查什么、怎样解释影响、遇到同步/安装目录应如何进一步核对；不是“目录匹配即推荐”的规则，也不能凭技能授予并不存在的操作能力。
- **工具层**：确定性工具负责目标空间、占用、身份、复制/校验、受支持的已知文件夹改址、逐项收据与恢复。普通目录、程序目录、云同步目录、Windows 已知文件夹使用不同操作语义；模型不得把一种路径改址泛化为搬整个 AppData 或程序目录。
- **UI 层**：复用摘要、对象列表、建议卡片、问题/选项与审阅结果。专用动作只在必要时出现专用控件；不允许模型生成任意脚本或 UI 代码。模型决定何时提问，程序将问题绑定当前任务和证据版本，用户回答回写结构化意图并继续循环。
- **问题语义**：“你偏好哪种方式”与“确认这批具体操作”分开。选项允许自由补充、跳过/稍后再说，回答偏好不默认为执行授权；旧问题在目标或计划变化后失效，不静默采用默认答案。只在答案会影响下一步时提问。
- **实施顺序**：先补工具/技能发现与按需读取、结构化问题及回答续接，再开发迁移/卸载等专用动作适配器。当前0.5尚无技能加载器、结构化选项问题组件或真实迁移，只有工具发现、文本补充与调查/模拟流程。

## D027：按需指导、用户直接操作与开发可见性（2026-11-02，v0.6）

- **经验成为指导**：把缓存、临时文件、下载、备份、系统升级、组件维护、休眠、分页、卸载和迁移经验整理成带条件、来源与版本的内置技能。模型先发现再按需读取，不把“关闭休眠”或固定分页大小当成所有电脑的通用清理规则。技能是经验，不是当前机器事实，也不开放新的系统操作。
- **两种发起方式**：模型可提交计划；用户也可从已解释的条目自行选择操作，由程序生成绑定身份的计划并直接执行同一核验流程，无需模型再发删除命令。记录保留来源、明确选择、逐项结果和恢复状态，并在继续任务时告知模型。当前两种方式都只接模拟后端。
- **问题与操作分开**：模型的问题以2到5个选项、自由补充和暂不回答呈现，绑定问题版本。选偏好不会批准处理；程序的确认处理按钮明确表达具体对象与动作。旧问题或对象变化时拒绝复用。
- **开发模式分开采集与显示**：记录默认关闭；实时显示、模型通信、技能内容与其他工具可分别选择。只在开发面板可见时刷新有界记录，阅读展开记录时暂存新内容，避免刷新表单和阅读位置。记录排除凭据、内部推理和不透明签名，不宣称可显示模型的所有私有思考。
- **外观取舍**：0.6 默认低眩光深色，提供浅色和跟随系统（0.7 按用户最新偏好改为默认跟随系统，见 D029）；主题、开发显示偏好随本机数据保存，不依赖每次变化的HTTP端口。保留简单导航和少量主操作，通过语义色、图标、层次与状态细节提升质感，不增加信息密度。

## D028：按用户当前需要分配信息权重（2026-11-02，v0.6收尾）

- **主层**：目标、当前结论、需要决定的问题和一个下一步操作。问题一次一个，不默认选答；失败和待核实状态及时出现，普通记录不争夺注意。

- **图标边界**：图标只从当前清单关联的本地资源异步读取，使用有界缓存，慢或不可用时降级为类型图标；不为取图运行所选程序，不访问远端，也不向 LLM 发送图像。图标可被替换或缺失，因此只辅助识别，不证明发布者、文件安全或可删除性，不能降低身份和保护核查。
- 图标的可见性懒请求由IntersectionObserver完成；已获取的PNG使用eager解码，否则hidden图片叠加原生lazy会一直不触发onload。该问题通过真实页面观察发现与复核，DOM夹具检查不能替代实际渲染。
- **指导扩展**：内置17类指导，`SKILL_VERSION='1.1.0'`；目录版本另由元数据指纹派生。缓存、系统与恢复、休眠分页、卸载迁移、云文件、虚拟盘、游戏开发、后台和浏览器隐私等经验均带条件与来源，按需加载，不作为当前机器事实或额外操作权限。
- **只读事实**：主任务共22个工具，新增 `collect_system_configuration(section='memory_power')` 与 `inspect_volume(scope_id)`。前者只读固定内存/分页/休眠能力与允许的配置值；后者只查已有任务根所在本地卷容量、当前用户可用空间与回收站统计。`list_scopes(purpose='volume')` 仅发现这些既有位置，文件任务不因此取得父目录遍历权。两项观察保留来源、时间、预算、部分状态和警告，返回 `actions: []`，不扩展目录、动作或任意注册表读取。配置不等于活动状态，未知不等于零，容量与回收站计数不等于健康或可恢复。
- **仍未实现**：真实删除、迁移、卸载和系统设置修改，以及 SMART、温度、固件、历史事件、完整电源策略、云状态与 WSL 内部调查等专门证据。指导存在、图标显示或模拟收据都不能当作这些能力已交付。
- **候选状态与重访**：本轮本机源码与最终产物验证已完成，确切范围由[发布记录](RELEASES.md)集中维护。先核对可读性、四协议、真实封装、隐私、图标降级和只读范围；再依据实际任务质量扩展采集与适配器。D029 的原创许可、第三方各自条款和公开二进制来源待办不变。

## D032：保存、偏好与流式反馈分别准确表达状态（2026-11-02，v0.9）

- **用户意图**：测试失败后不应丢掉填写内容或误以为密钥未保存；整理偏好应对所有模型通用且易于修改；公开回复需要真正边接收边阅读，原始诊断里的内部标签不能混同于 API 消息角色。

## D040：重复查找作为独立本地事实工具，采用大小分组与完整SHA-256（2026-11-02，v0.12候选）

- **用户意图**：重复文件是可程序化核对的事实，不需要每次请求LLM；应能直接指定目录查找。用户明确选择大小分组后计算SHA-256，不追加逐字节比较。
- **算法与I/O**：先只读枚举元数据，按大小形成候选，单例大小不读取内容；对合格候选完整读取并计算SHA-256。Windows通常不为所有普通文件预存并维护一个通用SHA-256，本工具自己计算，不把文件ID、时间或元数据签名当成内容哈希。参见[Microsoft Get-FileHash](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash)对内容哈希的说明。读取按块进行是实现方式，不是逐字节比较第二轮。
- **匹配语义**：同大小与完整SHA-256是很强的实践证据，哈希碰撞仍不是数学上的不可能；参见[NIST哈希定义](https://csrc.nist.gov/glossary/term/cryptographic_hash_function)。不宣称100%无碰撞或已逐字节证明。结果不判断纪念价值、应用引用、保留位置或备份必要性，也不自动决定删哪个副本。
- **边界与覆盖**：独立扫描请求限定1–8个绝对本地目录，条目/深度/读取量有预算，另有1200秒协作工作预算，后台job提供进度与取消；检查点预算不等于强制打断阻塞I/O。保护、项目、凭据、重解析路径及云端占位跳过，不触发云下载。候选在读前、打开句柄及读后核身份与元数据；变化、权限、取消与预算缺口标明partial。取消仅保留先前完整核验的组，未完成的当前大小组不作为确认结果。它不保证观察后文件不再变化，不能代替将来动作前复核。
- **实体与展示**：硬链接按文件身份单独分组，不混称独立副本；摘要只在本次调用内按已核验实体复用，不跨job使用旧哈希。结果最多返回200组、2000路径条目，保留本次已形成核验组的真实总数、逐组及全局省略数量，不能推断未扫描范围的重复总数；展示截断也标明不完整。组成员次数不是去重后的实体数量，逻辑重复大小不等于实际可回收空间，初版不估算可回收量。
- **主线不变**：新增`dedup`本地job不调用模型、不发布主库存、不写评分或处理计划，结果初版只读。旧明确选文件的核验入口继续兼容。LLM仍负责可选的用途分析与整理协作，这不是用固定清理表替换智能体。后续若将结果交给模型或执行器，必须另行冻结范围、身份、保留选择和授权。
- **验收与重访**：用自有相同/不同内容、同大小、硬链接、保护、云占位、读取变化、预算与取消样本验证；同时检查无模型连接/请求、主库存与评分不变、结果截断计数及无文件改动。真实Windows目录行为与最终UI另验收；候选合同不代表已完成发布。若长任务体验不足，再讨论有指纹的缓存或持久续接，不偷用过期哈希或将取消称为全范围完成。
