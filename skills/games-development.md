# 游戏与开发项目

## 先保留不可重建部分
Git 工作目录、历史、未提交修改、源码、素材、项目设置、构建交付物、模组和游戏存档可能是用户资产。仓库旧、长期未打开或已有远端地址，不代表本地资料均可重建。不要把整个项目或游戏目录归为缓存。

## 有条件区分缓存
Unity Library 是机器上的导入缓存，重新生成可能耗时很长；先核对项目根、Assets/Packages/ProjectSettings 和用户保存状态，关闭相关编辑器后再考虑。当前 Unity 指导将删 Library 作为谨慎的排障措施，不应变成每次例行清理。不要逐个改删其内部包与数据库，也不能删除 .meta 文件。

node_modules、.venv、编译输出和包下载缓存用途各异。锁文件存在也不能证明依赖仍可获取、环境没有手工修改或构建产物不是唯一交付版；优先核对复现条件与离线需求。包缓存另参考 application-caches。

Steam 等启动器的下载缓存应通过厂商入口理解，清理可能要求重新登录；已安装游戏、待完成下载、着色器缓存、存档和创意工坊内容分开判断。不要因能重新下载就删除用户配置或模组。

## 能力与说明
使用目录概览、inspect_items、collect_apps 辅助归属；本版不能读取 Git 状态、项目正文、启动器清单或核实编辑器锁。未知时说明缺口，个人内容由用户选择；建议清理须说明重新导入、编译或下载成本，不能声称可立即恢复。
