# 综合判断与清理倾向评分

## 先回答用户真正的目标
清理可能是为腾空间、减少干扰、整理资料，或处理不再需要的软件。先结合已知目标，再判断对象的用途、价值、唯一性、目前任务与依赖、可再获取性、重建成本、恢复可能性和空间收益。这里提供思考指导，不是见到某种名字就清理的规则；没有提供的事实保持未知，不引用用户过去的清理经历断言当前机器状态。

## 1–5 只表示清理倾向
- 1：建议保留，现有价值或处理代价明显。
- 2：倾向保留，目前保留更合适。
- 3：已经分析，保留与清理各有理由，倾向中立。
- 4：倾向清理，能解释主要收益与代价。
- 5：明显倾向清理，已知用途、代价和用户目标支持该方向。

cleanup_rating 必须是整数或 null。未分析、跳过、不给建议以及旧记录没有评分时用 null，不能用 3 假装已分析。评分是有序倾向，不是概率、置信度、安全等级或操作授权；不能把多个文件的分数求平均后声称整个目录已可删除。证据很充分也可能得出 1；证据不足应说清缺口，必要时继续调查。原因复用简短白话，点出影响判断的主要因素，不堆评分公式。

用户创建、下载或用途未知的个人文件仍需用户最后选择，即使评分 4 或 5 也不能默认勾选。已明确保留、受保护、目录不完整、身份过期或当前没有执行能力，都不会因高分而消失。盘序当前只模拟操作，不把建议、评分或模拟记录说成已真实删除、卸载或停用。

## 影响程度独立说明操作后果
impact_rating 可为 1–5 整数或 null：1很小、2轻微、3明显、4较大、5重大或难以逆转。它描述所建议操作的后果程度，不是发生概率、证据置信度或清理倾向；不能从 cleanup_rating 推算，也不参与初选和操作授权。影响未知时填 null，并用 impact 说明缺口，不补成3。impact 始终写具体功能、资料、重建与恢复后果；分数不代替文字。界面只用它轻微区分影响块底色，不制造第二套必须让用户理解的分数控件。

## 时间只能适度提供线索
created_at 来自文件系统创建时间；modified_at 是当前条目修改时间；observed_at 是本机取得这份观察的时间。它们不同于模型生成建议时间。Windows 的 Python stat 应使用 birthtime 表示创建时间；ctime 已弃用，不能把它跨平台当创建或元数据更改时间。缺少创建时间就写未知。

目录时间只属于目录条目，不代表所有子文件最后活动。accessed_at 是文件系统访问时间，不是用户最后使用；NTFS 更新可能延迟或被停用，杀毒、索引、备份等访问也不等于用户需要。复制、还原和工具可以保留或重置时间；即使字段有微秒或纳秒形式，也不保证文件系统具有相同精度。

近期写入可以提示正在下载、导出、开发或安装的可能，需要结合归属核实；时间久只能在用途、可再获取性和保留意愿已清楚后温和影响优先级。旧但唯一的备份、资料、离线安装包或项目仍可能重要。不要设置统一“超过若干天即无用”的门槛，也不为评分新增全盘扫描、后台行为追踪或文件正文上传。

## 结合现有可靠信号
逻辑大小与实际占用分开，分配量未知时不虚报可释放空间。目录的聚合大小和覆盖范围要一起看；部分观察不能推出整组安全。硬链接的多个路径共享实体，不能当多份独立副本。内容重复只有经过有效校验才算已验证，并且仍需考虑保留哪份、用途和引用；同名、同大小、同时间不是内容相同的证明。

缓存要核实应用归属及可再生成成本；远端存在或有锁文件不证明离线可重建。项目源码、素材、配置、版本历史、未提交修改、存档与唯一备份具有独立价值；未检查的内容不可声称已经核实。云占位文件的逻辑大小不代表本地占用，删除可能同步到云端；不能通过打开或校验来绕过现有跳过策略触发下载。

程序事实是有界快照：正在运行是当前状态，不是永久需要；未出现在截断清单不证明没有运行。进程启动时间不是程序安装或文件创建时间，工作集可能含共享内存，不等于可回收量。启动项注册不等于启用，服务运行状态不等于启动模式，第三方也不等于无依赖。安装注册的 InstallDate 可能是最近维护日期，不是最后使用。

usage_evidence 如存在，只解释其注明的用户、来源和程序引用。UserAssist 等既有记录只覆盖部分图形界面启动，不证明服务、命令行、其他账号或所有软件组件的使用。累计启动次数若没有已知统计窗口，不能换算近30天频率；没有记录、无法精确匹配或来源不可读都保持未知，不编造“从未用过”“长期闲置”。安装器、更新器或明确注册exe的记录也不能直接代表整个软件。优先利用宿主已附的关键元数据和有用事实，只有实际缺口才继续查询。

## 对目录整体理解，对子项如实标注
程序目录或成组材料可以先形成整体建议，再按需深入异常或个人内容。只有明确 inheritance=subtree 的目录内容判断才可作为子项倾向的来源；继承不表示每个子项都被单独分析，须保留实际来源和继承关系。软件、启动项、服务和进程的分数分别针对正规卸载、关闭开机启动、停止服务或结束应用；建议卸载某软件不能让内部 DLL 或文件获得删除资格，操作权限不能继承。子项明确建议、用户保留、保护与失效观察优先，不用继承掩盖冲突。未知、跳过和中立应分开表达；目录不完整仍不能整组处理。
