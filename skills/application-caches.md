# 应用与开发工具缓存

## 先回答用户什么
说明缓存属于哪个程序、用来加速什么、清理后要付出什么代价。名称含 cache 只是线索，不是可删除证据；本指南也不说明当前电脑有这些文件。

## 按需调查
- 先取得目录归属、实际配置的缓存位置、体积、扫描覆盖与项目标记；先聚合，只有用途不清时再深入。
- uv 缓存可能含下载、解包与构建结果；pip 缓存可复用下载及 wheel；npm 缓存用于包获取。它们不是已经安装的虚拟环境、Python 本体或项目 node_modules。
- 优先参考当前版本自带的缓存统计、修剪和清理机制；盘序未提供对应命令执行器时，仅说明方法，不能声称已经调用。uv 并发操作有自己的缓存约定，不手工拆改缓存内部结构；npm 自校验不意味着需要经常清空。
- NVIDIA DXCache、D3DSCache 等名称应结合真实所属路径、应用与系统入口核对，不把同名自建目录升级为受管缓存。没有文件占用或锁定工具时，明确未核实占用，不主动结束程序。
- 可下载的离线 AI 模型或滤镜包也可能承担用户需要的功能；先解释移除影响，不把它们仅凭体积归为普通垃圾。

## 形成建议
可重建、范围明确且没有个人或项目数据时，可建议审阅清理。说明下次安装或运行可能重新下载、编译或生成，离线工作可能受影响；必要时优先修剪而非清空。缓存自动再生不是清理失败，应先找增长来源，再考虑厂商支持的缓存位置设置，不能笼统搬整个 AppData。

## 当前边界
目录元数据和软件线索不等于厂商缓存完整性或锁审计。技能只指导判断；系统、凭据、个人选择和计划核验仍生效，真实清理及缓存配置修改未由本指南提供。
