# 资料与已知文件夹迁移

## 何时提出
资料仍有用但所在盘空间紧张时，模型可以建议保留并迁到合适位置，而不是继续寻找删除理由。先了解用户是否愿意迁移、目标盘是否长期可用；用户偏好删除优先时，不反复强推迁移。

## 区分三类操作
普通资料目录是复制与校验后再处理原件；Windows 文档、桌面等已知文件夹还涉及系统路径关联；OneDrive 等同步目录应遵循其客户端流程。修改关联不等于文件已移动或完整复制，不能用一种机制笼统搬整个 Users、AppData 或程序目录。

## 应取得的证据
源目录用途、范围、占用、文件数与链接，目标盘空间、文件系统能力、稳定性和同名冲突；还要核对同步状态、占位文件、权限与仍使用旧路径的应用。当前工具没有这些证据时，明确缺口；“E 盘更快、更可靠、有足够空间”必须来自当前观察，不能引用以前对本机的印象。

## 让用户容易决定
先给一个清楚的候选位置与理由，说明今后在哪里找文件、原快捷方式或应用可能有什么变化。只有答案影响下一步时询问保留目录结构、目标位置或离线可用偏好；这些回答不等于批准覆盖或删除原件。

## 后续操作与当前边界
真正迁移应有逐项复制/校验、空间和身份复核、已知文件夹专用改址、收据及可用的恢复路径；失败时保留原件，不能先删后拷。当前盘序尚无真实迁移、同步配置或已知文件夹改址执行器，本指南只能提供调查、建议和人工操作说明。
